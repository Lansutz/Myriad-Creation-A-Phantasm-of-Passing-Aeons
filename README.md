# Myriad Creation: A Phantasm of Passing Aeons
## 纷繁的世界：一场流逝的幻景

一款基于学术研究的大战略文明模拟游戏。以唯物史观、布罗代尔三时段理论、人类学、技术史、反辉格史观、地理历史学、历史政治学等研究为理论基础，模拟文明从游群到帝国的完整演进过程。

> **关于本项目的开发方式**：本项目大量使用了 AI 辅助编程和文档撰写，但游戏的核心设计理念、系统架构、创新机制和学术判断均出自我个人的思考和研究。AI 是工具，不是设计者。文中提到的"我"指的是项目的独立设计者。
>
> **开发状态**：持续开发中，很多系统还只是框架，细节会随着开发不断调整。

## 一、学术基础与设计理念

### 史学理论
- **唯物史观** — 生产力与生产关系的矛盾运动推动社会变革
- **布罗代尔三时段** — 长时段（地理/生态）、中时段（经济/社会周期）、短时段（事件/人物）
- **反辉格史观** — 避免以今度古，尊重历史语境的复杂性
- **历史政治学** — 国家形成、制度变迁、权力结构的历史分析

### 社会科学
- **人类学** — 亲属制度、仪式、象征、文化相对主义
- **地理历史学** — 地理环境对历史进程的塑造与限制
- **技术史** — 技术演进的路径依赖、偶然性与社会嵌入
- **年鉴学派** — 总体史、问题史学、跨学科方法

### 核心设计原则

**文明演进的多路径** — 不预设"进步"的线性叙事。文明可以通过定居农业、游牧征服、贸易控制、宗教统一、军事联盟等多条路径形成国家。同一文化阶段可以有不同的移动模式和经济基础。

**地理决定论与能动性的平衡** — 地理条件决定物产与初始可能性，但不决定最终命运。物产→革新→路径依赖，历史充满偶然性与天才人物的突破。

**社会分层的渐进性** — 从平等的游群，到氏族部落，到酋邦的初步分层，到国家的完整阶级结构。每个阶层的出现都需要特定的革新与社会条件。

**革新是核心驱动力** — 很多东西都是由革新系统推动的，不只是技术，还包括思想、制度、社会结构的变化。革新在整个游戏中占据很大比重。

## 二、核心游戏系统

### 2.1 世界与地理

**世界生成**的核心思路是：地理不是背景板，而是历史的第一推动力。我不希望玩家看到的是一张随机噪声地图，而是一个有逻辑的生态结构——山脉阻挡水汽形成雨影效应，大河沿岸孕育冲积平原，河口三角洲天然适合建城。

实现上基于多层高度图叠加生成地形，再用水力侵蚀算法雕刻河谷，最后用简化的大气环流模型计算温度和降水分布。群系（biome）的所有参数都通过 JSON 定义，方便后续调整和模组化。水文系统包括河流生成、流域划分和河口三角洲。省份被设计为包含多个子地块的结构，支持地块级别的精细模拟。

这部分的依据主要来自地理历史学和环境史的研究——地理环境不决定历史，但它深刻地塑造了历史的可能性空间。

### 2.2 人口与社会

**人口与聚落**：人口不是抽象的数字，而是由具体阶层构成的社会实体。人口承载由地理承载力（耕地、水源、气候）、仓储承载力（粮仓容量）和贸易修正（商路补给）共同决定。

聚落（村镇、城、堡垒）被设计为独立于地块的实体，有自己的等级、形态和辐射范围。这是因为前现代的聚落不是地块的附属品，而是一个有自身生命力的节点。聚落的形态也不是永久标签——村镇可以发展为城，堡可以转型为城，城也可能因战乱强化为堡垒。

聚落摧毁系统设计了三级程度（轻度劫掠、中度破城、重度夷平）和六种手段（劫掠、纵火、拆城、水淹、屠城、夷平）。这参考了历史上的真实案例——汉谟拉比毁玛睿、杨坚毁建康、赵炅毁晋阳——摧毁的手段和程度各不相同，后果也不一样。摧毁后会引发连锁反应：人口流失为流民，地块变无主，秩序下降导致盗匪和蛮族滋生。

**社会阶层与派系**是整个游戏中文件最多的模块之一，因为我相信社会结构是理解前现代历史的关键。

阶层系统参考了人类学对前现代社会的研究，将人口划分为农民（自耕农、佃农、农奴、雇农）、自由民（市民、商人、工匠、士人）、奴隶（家奴、官奴、债务奴、战俘奴）、王室和贵族教士几个阶层。每个阶层有独特的需求维度——农民需要土地和粮食安全，市民需要贸易和手工业机会，贵族需要权力和地位。需求得不到满足会引发不满、迁徙甚至叛乱。

**阶层与革新的关系**是这个系统最重要的设计之一。我不认为所有社会都有相同的阶层结构——不同的社会，因为技术水平、思想观念和经济基础不同，拥有的阶层并不完全一致。一个没有农业技术的游群社会不可能有农民阶层，一个没有私有财产观念的社会不可能有佃农阶层，一个没有官僚制度的社会不可能有士人阶层。

因此，**固定阶层在某个社会或政权下的产生，需要有相应的革新作为前提**——不管是技术方面的还是思想方面的。比如：
- 农业革新（技术）解锁自耕农阶层
- 土地私有观念（思想）解锁佃农阶层
- 庄园制度（制度）解锁农奴阶层
- 金属冶炼和手工业分工（技术）解锁工匠阶层
- 货币和市场经济（经济）解锁商人阶层
- 文字和官僚制度（技术+制度）解锁士人阶层
- 世袭首领制度（思想）解锁贵族阶层
- 战俘奴役观念（思想）解锁奴隶阶层

这不是一个简单的"解锁"机制，而是一个社会结构随技术和思想进步而逐渐分化的过程。

**派系系统**的设计基于一个观察：前现代政治的核心冲突往往不是个人之间的，而是基于阶层利益的派系斗争。派系有阶层基础（各阶层对派系的支持权重，可以跨阶层结盟）、领袖角色、成员名单和政治纲领。派系可以推动法律改革、支持或反对继承、甚至发动叛乱。

**社会分化**系统追踪社会分层的完整度——这是文化阶段提升的核心指标之一。从平等的游群，到初步分层的酋邦，到完整分层的国家，社会分化是一个渐进的过程，不是突变。

这部分的设计依据主要来自历史社会学和人类学对前现代社会分层的研究，包括韦伯的阶层理论、马克思的阶级分析，以及人类学对酋邦和早期国家的研究。需要说明的是，阶层的具体划分（农民四层、自由民四类、奴隶四源）和阶层需求系统的设计是我自己的创新，不是直接套用任何现有理论。

### 2.3 经济与革新

**经济**系统的核心逻辑是一条因果链：地理决定物产，物产决定可学习的革新，革新提升生产效率，生产剩余支撑社会分层和国家形成。没有铁矿的地区无法发展金属冶炼，没有适合耕作的土地无法支撑农业文明——这不是刻意的限制，而是历史的真实。

商品系统定义了各种物产和加工品，商品有不同的类型和品质等级。加工品的品质（差、普通、优良、精良）受原材料库存、工匠技能和技术水平影响——原材料不足时品质会下降。这参考了技术史中关于"生产实践积累"的研究。

货币系统处理货币的发行、流通和价值。税收系统支持多种税收类型——农业税、商税、人头税、畜牧税、保护费。贸易系统包括贸易中心、贸易路线和商队。高等级聚落对周边形成经济虹吸效应——税收和贸易向中心聚集。这参考了历史地理学中关于中心地理论和经济地理学的研究。

社会阶层可用性系统定义了每个阶层出现需要哪些革新和文化传统——这是社会分层渐进性的具体实现。社会分层计算器自动计算社会的分层完整度——这是文化阶段提升的核心指标之一。

需要再次强调的是，经济系统的很多变化都是由革新推动的——新的生产技术提升效率，新的经济制度（如货币、税收、贸易制度）改变经济结构，新的思想观念（如私有财产、市场观念）改变人们的经济行为。革新不是一个独立的"科技树"，而是渗透到经济、社会、政治、文化各个系统中的核心驱动力。

**革新**系统是整个游戏中占比重最大的系统之一。这个系统的设计是为了回应一个问题：技术进步是怎么发生的？我拒绝线性的"科技树"叙事，因为技术史的研究表明，技术演进是路径依赖的、充满偶然性的、受社会条件约束的。

革新采用**两级分类**：大类（技术/思维/制度/传统）× 子类。大类是借鉴了技术史和知识社会学的分类方法，子类的具体划分是我自己设计的。革新定义全部数据驱动，由 JSON 文件加载，支持模组覆盖和新增。

每类革新有明确的前置关系，但前置链不是唯一的——同一项革新可能有不同的前置路径。

革新进度由两条路径共同推动：一是社会总体的生产实践积累（生产数量乘以品质，但边际收益递减），二是个人化的突破（工匠、商人等角色在旧方法实践达到阈值后迸发新灵感）。这参考了技术史中关于"学习曲线"和"天才突破"的讨论——大多数技术进步是缓慢的实践积累，但关键时刻的天才人物可以带来跨越式发展。

需要强调的是，天才不能凭空创造——没有铜的地区，再天才的工匠也无法发明青铜冶炼。物产是革新学习的前置条件，至少需要一定数量的相关物产才能开始积累研究进度。

角色研究系统追踪具体角色对革新的贡献——不是抽象的"国家在研究"，而是具体的工匠、学者在推动技术进步。

### 2.4 文化与宗教

**文化**系统的核心是"文化阶段"——游群、部落、酋邦、族群、高度文明——这参考了人类学的经典框架（塞维斯的四阶段论），并在此基础上扩展。这不是线性的"进步"叙事，而是社会复杂度的提升——每个阶段都可以有不同的移动模式和经济基础。

**文化数据的七大板块**是文化系统的核心设计——这是我参考考古学文化研究方法后自己设计的框架。每个文化都由七个维度定义：
1. **生计主轴**（狩猎采集/渔猎/早期畜牧/管理型采集）
2. **移动模式**（高度流动/季节性营地/半定居）
3. **葬俗类型**（竖穴墓/二次葬/瓮棺/屈肢葬/仰身葬/赭石施用，可多选）
4. **原始崇拜权重向量**（七维：生殖/自然/祖先/死亡/图腾/形象/巫术，0-100相对配比）
5. **物质风格倾向**（石器组合/陶器/骨器偏好）
6. **象征实践焦点**（动物力量/生殖/山石/死亡处理，主+次双焦点）
7. **环境适应标签**（草原/河谷/森林边缘/海岸/山地，可多选）

这种设计参考了考古学中"考古学文化"的定义方法——一个考古学文化通常由一组共同的器物组合、葬俗、居住方式来定义。但将其系统化、可量化为七大板块，是我自己的设计。

移动模式和生计类型是两个独立的维度。这里需要特别澄清：海洋城邦是定居模式加海洋贸易经济，不是半定居——它的城市是永久固定的，只是经济依赖海洋贸易。半定居（季节性营地）指的是渔猎族群那种有冬夏营地的模式。

**国家形成**被设计为五条可能的路径：定居农业路径、游牧征服路径、贸易控制路径、宗教统一路径、军事联盟路径。这参考了比较人类学和国家形成理论的研究——国家不是只有一种形成方式。

**扈从制**被设计为酋邦阶段的核心制度——首领通过私人扈从队积累武力，扈从的忠诚是人身依附关系。这参考了塔西佗《日耳曼尼亚志》中对日耳曼扈从制（Comitatus）的描述，以及恩格斯关于扈从制促进王权产生的论断。

**什么是文明？**这是一个学术界长期争论的问题，我在设计中采用了"新标准为主，旧三要素为参考"的立场。

旧的"文明三要素"标准（城市、文字、青铜器）来自考古学——因为考古学家只能发掘出城市遗址、文字遗物和青铜器，所以这三者成为了判断文明的标准。但这个标准有明显的缺陷：
- 玛雅文明没有青铜器，但公认是文明
- 印加帝国没有文字，但公认是文明
- 非洲的许多王国没有文字和青铜器，但有完整的社会分层和专业化生产

因此，学术界越来越倾向于使用**新标准**来定义文明/国家：
1. **专业化生产** — 有专门的工匠、商人、军人阶层，他们不再自己生产食物，靠赋税或贸易养活
2. **完整的社会分层和分工** — 有明确的统治阶级和被统治阶级，贵族/平民/奴隶三层基本成型
3. **城市化** — 至少有一个等级足够高的定居点（城国），或固定的中心营地加季节性营地体系（行国）
4. **强制性权力** — 有常备军和官僚/贵族议事机构，能强制征收赋税和劳役
5. **领土控制** — 对一定范围的领土或活动范围有实际控制（能驱逐入侵者、能征税）

在游戏中，这五个标准是文化阶段从"族群"提升到"高度文明"的必要条件。旧三要素（城市、文字、青铜器）则作为"成就条件"——不是必要的，但有重大加成（文字提升管理效率和知识传播速度，青铜器提升军事和生产效率）。这种设计允许玩家在没有文字或青铜器的情况下仍然可以形成文明，就像历史上的印加和玛雅一样。

**宗教**系统是设计得最深入的模块之一，因为我相信宗教在前现代社会中扮演了远超"信仰"的角色——它是法律、教育、艺术、政治合法性、社会凝聚的核心。

**双维度宗教谱系**是这个系统最核心的设计。宗教不是简单的树状结构，而是两个独立维度的交叉：
- **组织谱系**（组织父）：宗教→宗派（组织性分裂，互斥）→传统（思想性传承，可共存）→分支传统（任意深度）
- **思想谱系**（学派父）：思想源链——礼仪祖先学派，与组织谱系独立

这种设计是为了捕捉历史上宗教的复杂性——比如聂斯托里派在组织上是独立的宗派，但在思想上可以追溯到安提阿学派；亚述教会在组织上有使徒统绪，但在思想上源自赛琉基亚-泰西封学派。

**教统**（使徒统绪/法脉）是组织连续性的标志——宗派必须有教统，没有教统的学派只能思想并入，不能独立组织化。这参考了基督教的使徒统绪、佛教的法脉传承等概念。

教义系统允许自定义宗教的核心教义，每个教义有多个选项。教义影响宗教的法律、道德判定和社会效果。

神祇系统支持多神教和一神教，每个神祇有自己的属性、崇拜方式和神职人员。

**封圣与主保圣人系统**：虔诚且有美德的角色可以被封圣，圣人有自己的纪念日、崇拜和主保范围（某个城市、行业、群体的保护者）。

需要特别说明的是，**主保圣人制度很大程度上是多神教万神殿传统的衍生和残留**，而不是简单的"人神化"。多神教的起源大致是这样的：各个小部落有自己的守护神，各个城邦有自己的城邦守护神——这些神祇最初是独立的。随着部落征战、融合，这些独立的守护神被编进一个大的谱系，形成了**万神殿系统（Pantheon）**——在这个系统中，人们选择一个或几个神祇去崇拜，每个地方、每个城市、每个行业都有自己的主保神祇。

当一神教（如基督教）向多神教地区传播时，它不可能完全剥离这些成分——如果完全剥离了，它就没有传播的土壤。人们已经习惯了有一个"保护着我们这个城市/行业/群体的神圣存在"，如果一神教说"你们的神都是假的，只有我们的神是真的"，传播会非常困难。因此，一神教采取了一种文化适应的策略：将原来各地守护神的传统，转化为**主保圣人制度**——原来罗马时期各个神庙供奉的神祇，变成了各个城市的主保圣人。这样，人们的信仰习惯得到了保留，只是崇拜对象从多神教的神祇变成了一神教框架下的圣人。

因此，封圣系统不仅适用于一神教，也适用于多神教和原始宗教——在多神教中，对应的就是万神殿中的神祇选择和主保神祇崇拜；在一神教中，对应的就是封圣和主保圣人制度。两者共享同一套底层逻辑：每个地方、每个群体需要一个"保护者"，可以是神，也可以是被神化的人。

**神祇的起源与演化**是宗教系统的另一个核心设计。比较宗教学的研究表明，神祇不是凭空出现的，而是有其历史起源和演化过程：
- 最初，一个部落就有一个神祇——每个部落有自己的保护神，神祇与部落的身份认同紧密绑定
- 部落之间征战、融合，形成大部族——被征服部落的神祇不会立刻消失，而是与征服者的神祇发生关系
- 大部族有部族守护神，城国/城邦最初也是城邦守护神（雅典的雅典娜、斯巴达的阿尔忒弥斯、罗马的朱庇特）
- 最初会有很多守护神

随着历史的发展和政治实体地位的更迭，这些神祇的命运各不相同：
- 某些神祇消亡在历史长河中——当一个部落被彻底征服或同化，其神祇可能被遗忘
- 一些神祇被编进了神谱，变成了下位的存在——征服者不会完全消灭被征服者的神祇，而是将其纳入自己的神谱，作为主神的下属、配偶、子女或对手。这就是为什么希腊神话、北欧神话、印度教神话中有如此庞大的神祇谱系——很多下位神其实是被征服部落的保护神

在游戏中，这个过程被模拟为：当两个不同宗教的政治实体发生接触、征服或融合时，神祇系统会发生相应的变化——被征服方的神祇可能消亡，也可能被纳入征服方的神谱成为下位神。这不是一个简单的"宗教转换"，而是一个神祇谱系的重组过程。

**多神教与一神教共享同一套框架**。整个宗教系统的设计遵循一个通用框架——神祇、教义、仪式、神职人员、圣地、法律、传教——但不同类型的宗教在这个框架下有不同的复杂度：
- 一神教通常有更复杂的教统机制、更严格的教义正统性判定、更完善的教会组织
- 多神教通常没有教统这种复杂机制，神祇之间的关系更灵活，教义更松散，更容易吸收外来神祇
- 更原始一点的宗教（泛灵论、祖先崇拜、mana信仰）连完整的神祇谱系都没有，崇拜对象更分散，仪式更简单

但它们都遵循同一套底层逻辑——神圣与世俗的区分、仪式的重复性、神职人员的专业化、圣地的空间性、教义的解释权。这种设计参考了伊利亚德的比较宗教学框架（神圣与世俗、永恒回归、中心象征），以及缪勒、弗雷泽、涂尔干等学者对宗教起源和演化的研究。

法律与犯罪系统：宗教法律定义了什么是罪行，罪行有不同的类型和惩罚方式。审判系统处理宗教犯罪，有不同的裁决类型。这参考了中世纪的宗教裁判所、伊斯兰的沙里亚法庭等。

传教系统：传教士可以在异教地区传播信仰，信仰传播有不同的阶段和方式。

思想流派与意识形态运动：宗教内部可以产生不同的思想流派，流派可以演化为意识形态运动，推动宗教改革或分裂。这参考了宗教改革、伊斯兰的教法学派等历史现象。

宇宙观形态支持一神、多神、二元、泛灵、祭祀型、mana等不同类型的宗教世界观。

### 2.5 政治与外交

**行国与城国**是整个游戏最核心的设计之一，也是最容易被误解的地方。

首先需要澄清：前现代国家没有现代意义上的"固定边界"。无论是城国还是行国，领土都是模糊的、势力范围式的。我们说的"行国与城国"不是"有边界 vs 没边界"的区别，而是两种根本不同的组织逻辑。

**城国**（定居政权）以固定的定居点为基础，经济主要依赖农业、贸易和税收，军事以常备军和守城战为主。它的核心资产是土地和城市。

**行国**（游牧政权）以移动的人群和牲畜为基础，王庭随季节在冬营地和夏营地之间迁徙，经济主要依赖畜牧、劫掠和对被征服定居区征收的保护费，军事是全民皆兵的骑兵，擅长机动和诱敌深入。它的核心资产是人和牲畜，而不是土地——所以行国不需要防守每一寸土地，拔营即走。

行国可以征服和控制定居城市（作为附庸或纳税地），但王庭本身不固定。行国也可以通过定居化改革转化为城国——这需要农业技术、城市建设和官僚制度的建立。城国罕见游牧化，通常是被游牧民族征服后统治阶层发生游牧化。

这个设计的依据主要来自中国史学界对"行国"与"城国"的经典区分（如司马迁《史记》中对匈奴的描述），以及人类学对游牧社会的研究。

**政治与政体**系统不使用"君主制/共和制"的简单二分，而是设计为七个维度的组合：最高权力归谁、权力如何交接、中央机构是什么、地方如何治理、头衔如何分配、继承法如何规定、城市有多少自治权。

这样设计是因为历史上的政体远比"君主/共和"复杂——罗马帝国是君主制但有元老院，神圣罗马帝国是选举君主制，威尼斯是共和制但有世袭贵族。一个君主制国家可以有中央机构，可以用选举方式交接权力，可以同时存在封建和官僚两种地方治理方式。

最高权力的交接方式决定了政体的基本形态——个人传承系（世袭、僭夺、神命）推导为君主，选举系（选举、轮座）根据权力分配推导为选举君主或共和。"王国""帝国"等只是外交头衔（纯称号，不产生机制影响）。

继承法被细分为范围（本族/血亲不论姓氏）、支系（长支优先/兄终弟及）、性别（仅男/男优先/平等/仅女/女优先）和长幼。最高权力的交接可以有主要方式和次要方式——比如罗马到东罗马，僭主制是主导，推举制是第一次要，血缘世袭是第二次要。

中央机构先选"有无"，再选类型（长老会、元老院、议会、官僚机构）。选了议会才会有议会构成等子选项（一院、两院、按等级分庭）。君主制下也可以有中央机构。

地方治理的封建类型和官僚类型是两个选项组，各自下面有不同的方式和范围选项。封建和官僚不必然互斥，但它们的子选项组有一定互斥性。

官职系统定义了各种官职的名称、职责和任命方式。

政权更迭系统追踪政权的结构性张力和关键节点——当社会矛盾积累到一定程度时，会触发关键节点（Juncture），可能导致政权更迭、改革或内战。这参考了历史社会学中关于国家崩溃和革命的研究。

政体的变化也往往是由革新推动的——官僚制度的建立需要文字和行政技术，封建制度的形成需要土地私有和军事依附观念，共和制度的出现需要公民观念和议事传统，选举制度的运作需要相应的政治思想。政体不是凭空选择的，而是社会的技术水平、思想观念和经济基础发展到一定阶段后的产物。

这部分的设计依据主要来自历史政治学和比较政治学对前现代政体的研究。需要说明的是，政体七维组合模型中，"最高权力/中央/地方三个层级×交接/分配两问"的基本框架借鉴了比较政治学的结构分析方法，但具体的七维划分、选项设计和组合约束规则是我自己设计的。

**外交**系统的一个核心设计是：敌对是常态，宣战是例外。我不希望玩家被"没有宣战理由不能开战"束缚——在敌对状态下，可以直接发动局部入侵、劫掠城镇、攻击聚落。但每一次敌对行动都会给对方制造战争借口，也会损害国际名声。正式宣战开启全面战争，不宣而战承担名声损耗。

战争借口、战争目标和和平条约被设计为三层分离的——开战的理由不一定等于想要的结果。条约谈判时，双方各有"让步"和"索取"清单，可选项受战争分数限制。

外交关系设计了十种类型：平等盟约五种（互不侵犯、防御同盟、进攻同盟、全面同盟、阵营），不平等从属五种（朝贡、附庸、附属、保护国、傀儡）。封建附庸是内政关系，不是外交关系。

通行管制分四级——在严格管制地区，军队通过必须请求军事通行权。

和平谈判系统处理战争结束时的条约签订，有谈判状态和条款系统。

这部分的设计参考了历史国际关系学和战争史的研究，特别是关于前现代国际关系中"灰色地带"冲突的研究。

### 2.6 军事与战争

军事系统的核心不是兵力数字，而是组织度、士气和训练度三者的互动。组织度决定部队能持续战斗多久，士气决定是否会崩溃，训练度决定组织度掉得有多慢。

这样设计是因为军事史的研究表明，前现代战争的胜负往往不取决于人数，而取决于部队的凝聚力和纪律性。一支训练有素的小部队可以在有利地形击败人数众多但组织度低下的大军。

**三军编制系统**是军事系统的基础框架——前军/中军/后军（或左军/中军/右军）的军队编制。这是我参考中国古代军事编制（如春秋时期的三军制）和世界军事史中的阵型部署后自己设计的系统。每个军有不同的战术角色：前军负责先锋和试探，中军是主力和指挥核心，后军负责预备队和撤退掩护。不同的阵型部署会影响战斗结果——比如前军强势可以快速突破，但后军薄弱则容易被包抄。

兵种系统分为步兵、骑兵、海军三个大类，每个兵种有：
- **等级**（tier）：1轻型、2中型、3重型、4超重型
- **战斗属性**：近战攻击、远程攻击、防御、士气、速度、补给消耗
- **招募消耗**：物资消耗和人力消耗
- **地形偏好**：不同地形下的战斗修正
- **解锁前置革新**：兵种必须有对应革新才能征募（如重骑兵需要马镫革新）

这种设计的核心思路是：兵种不是凭空出现的，而是技术革新和社会条件发展到一定阶段后的产物。没有马镫就没有重骑兵，没有造船技术就没有海军。

战斗系统处理两军交战的结算，采用分阶段战斗推进（最多5个阶段），总伤亡率和瞬时伤亡率分开计算，组织度过低会增加敌方追击效率，瞬时伤亡率过高会瞬间降低组织度，极端情况下可能触发踩踏事件——踩踏是军事战斗系统中的一个机制，不是独立的灾害系统。

行军与寻路系统处理军队在地图上的移动。通行系统不设硬性的不可通行——山脉地区通行难度高，但并非完全无法通过。

关隘与堡垒系统：关隘仅可在狭窄地形修建，可以直接阻挡通行；堡垒不直接阻挡通行，但敌对部队经过时受行军损耗和速度影响。

大圣战系统处理宗教性的大规模战争——如十字军、吉哈德等。大圣战有自己的状态机和规则。

营寨系统：军队、盗匪、蛮族都可以建立营寨（行军营地、冬营、山寨、毡帐群），营寨可以随时间升级为坞堡甚至聚落。

军队以100人为一个编制块，补员按一定比例批量增加——这主要是出于性能考虑，避免逐人计算的CPU负担。

### 2.7 角色与事件

**角色**系统是另一个大模块，因为我相信历史是由具体的人推动的——不是抽象的"国家"在做决策，而是有性格、有关系、有欲望的具体人物。

角色数据包括基本属性（年龄、性别、生日）、性格特质、经济原型、社会角色、精神健康状态等。

性格系统采用多维度模型——不是简单的"善良/邪恶"二分，而是多个性格维度的组合，每个维度有不同的特质。性格会影响角色的决策、关系和事件触发。角色还可以有精神障碍——这不是为了猎奇，而是因为历史上很多重要人物确实有精神健康问题，这些问题影响了他们的决策和历史进程。

关系系统包括角色之间的纽带（友谊、敌对、忠诚、怨恨等）和关系类型。关系不是静态的，会随着事件和互动变化。

家族系统追踪家族谱系和继承关系。家族不是简单的血缘树，而是有政治意义的实体——家族之间可以结盟、联姻、对抗。

绰号系统为角色生成基于其事迹和性格的绰号（如"大帝""无畏者""昏庸者"），绰号有不同的层级和褒贬含义。这参考了历史上统治者绰号的传统——从罗马皇帝的"奥古斯都"到中世纪国王的"狮心王"。

评价系统记录角色在不同维度上的历史评价——不是简单的"好/坏"，而是多个评价维度的综合。

这部分的设计依据主要来自历史人物研究和心理史学的尝试——我不试图精确模拟历史人物的心理，而是试图捕捉性格和关系如何影响历史决策。

**事件与编年史**系统处理游戏中的各种随机和历史事件。事件有不同的类型，可以触发各种效果。事件系统是模组化的——模组可以添加新的事件。

编年史系统记录游戏世界中发生的重要事件，形成一个可追溯的历史记录。玩家可以回顾自己文明的历史——哪些关键事件塑造了现在的局面。这参考了年鉴学派中关于"事件史"的研究——虽然布罗代尔强调长时段，但短时段的事件仍然是历史的重要组成部分。

### 2.8 世界生态与自主单位

**MapActor 自主单位**是可以在地图上自主行动的单位，不一定隶属于任何政权。

设计这个系统有几个深层原因：

**第一，解决政权边界化的问题。**很多大战略游戏有一个共同的问题——地图被各种政权的色块填满，每一寸土地都属于某个政权，边界清晰得像现代民族国家。这在模拟上是不真实的——前现代世界的大部分土地其实是"无主"的，政权的实际控制范围远小于地图上画的边界。边境地区往往是模糊的、 contested 的、充满了各种非国家行为体的。我不希望地图被色块填满，而是希望有大量的"灰色地带"——无主的土地、蛮族的活动范围、商队的贸易路线、流民的迁徙路径——这些都由 MapActor 来填充。

**第二，让世界更有生命力。**我不希望地图上只有国家和军队在活动——商队在贸易路线上穿梭，流民在战乱后迁徙，蛮族在边境游荡，盗匪在低秩序地区滋生，雇佣兵等待出价最高的雇主。这些自主单位让世界感觉像是一个活着的生态系统，而不是一个只有玩家和AI政权在博弈的棋盘。

这些自主单位有自己的 AI 和行动逻辑，不同类型有不同的决策间隔（流民每天思考，游牧民每三天，野兽每七天）以控制性能开销。

前国家形态的人类群体——游群、部落、酋邦——以 MapActor 的形式存在于地图上。当它们满足人口、领袖、领土和文化条件时，可以转化为正式政权。这为游戏提供了"蛮族建国"的可能性，也让世界更有生命力。

弃地与聚落摧毁的联动：聚落被摧毁后产生流民 MapActor，地块变无主后蛮族/盗匪滋生，蛮族占据弃地建立营地形成活动范围，可被招安或征服——这是一个完整的生态循环。

## 三、技术架构

### 引擎与语言
- **Unity 6000.6.0f1** — URP 渲染管线
- **C# 9.0** — netstandard2.1
- **模块化程序集** — 6 个 asmdef 单向依赖链

### 模块结构
```
Core              — 数据定义、枚举、本地化
World             — 地形、气候、水文、群系、省份、聚落
Simulation        — 人口、经济、革新、文化、宗教、社会、政治、战争、角色
Rendering         — 地图渲染、覆盖层
Infrastructure    — 存档、模组、序列化、事件系统、音频
UI                — 界面系统、控件、面板
Editor            — 地图编辑器、地形绘制、省份编辑
```

### UI 材质体系
暖灰褐磨砂石材 + 做旧青铜 + 灰米色旧纸的统一设计语言：
- **主面板** — 暖灰褐磨砂石材（载体）
- **Tab** — 嵌入式标签，Active 底部青铜强调线
- **Button** — 稍亮磨砂石材，四状态过渡
- **InputField** — 内凹暗槽，Focus 青铜焦点线
- **Scrollbar** — 凹槽 + 凸起滑块
- **ProgressBar** — 凹槽 + 九语义色填充
- **Tooltip** — 灰米色旧纸信息层

### 字体系统
- **思源黑体** — 功能文字（按钮、Tab、数字、正文）
- **思源宋体** — 身份文字（人物、文化、国家名称、历史文本）

### AI 系统
AI 系统控制非玩家角色和政权的行为。AI 有不同的决策类型（建造、外交、军事等）、目标系统、性格和立场。AI 的决策不是脚本化的，而是基于目标和性格的动态选择——不同性格的 AI 会做出不同的决策。聚落 AI 专门处理聚落的自主发展——即使没有玩家干预，聚落也会根据经济、人口和安全状况自主发展。

### 模组与存档
模组系统支持游戏内容的模组化——群系、商品、革新、宗教、事件等都可以通过 JSON 或脚本添加和修改。这是因为我相信一个历史模拟游戏的生命力在于玩家社区的创造。

存档系统支持游戏状态的保存和加载，包括世界状态、所有角色、所有政权、所有事件等。存档格式设计为可扩展的，方便后续添加新系统。

### 音频
音频系统处理游戏中的音乐和音效。虽然目前还比较基础，但设计目标是根据游戏的时代、地区和情境动态调整音乐——和平时期的舒缓旋律、战争时期的紧张节奏、不同文化地区的不同音乐风格。

### 灾害与疾病
灾害系统模拟前现代社会面临的各种自然灾害和流行病。灾害有不同的类型（气象、地质、生物等）、频率、持续时间和严重程度。

疾病系统是灾害系统的一个重要子系统。疾病有不同的类型（传染病、地方病等），可以在人口中传播，造成人口损失和社会动荡。这参考了医疗社会史和疾病史的研究——如黑死病对欧洲社会的深远影响。
