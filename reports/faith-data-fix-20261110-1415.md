## 四、为什么"上溯兜底"在这 8 条上恒为 0（代码成因，非内容独有）

`GameWorld.Core.cs` 的挂宗派逻辑三段（行号为本轮工作区实际行号）：

1. `:1049` **默认宗派的合成 id 是负数**：`denominationId = -100000 - value.religionId`；
2. `:1071-1084` **直挂**：按 `faith.religionId` 直查 `byId`（显式宗派）或 `defaultByReligion`（按 religionId 建键）——14 条走这条；
3. `:1087-1099` **上溯兜底**（沿 `parentReligionId` 爬）：命中 `byId` 或 `defaultByReligion` 即得锚点；
4. `:1100` 判定：`if (anchorDenom >= 0 && byId.TryGetValue(anchorDenom, out ...))`。

**缺陷就在这里**：上溯一旦命中"默认宗派"，`anchorDenom` 取的是它的 `denominationId`，即 `:1049` 造出来的**负数**（如 −100100），于是 `anchorDenom >= 0` 恒假 ⇒ 兜底永远不成立 ⇒ `上溯锚点 0 个`。这不是"父节点无父"，是负号段 id 与 `>= 0` 守卫不兼容。

**复现证据（用真实数据 + 真实守卫做算法复刻，脚本见 §六.4）**：
```
REPRO(pre-fix data + code guard anchorDenom >= 0): attached=14 reanchored=0 orphan=8
orphans=104(罗马公教会), 105(正统大公教会), 120(亚历山大科普特正教会), 121(安条克叙利亚正教会),
        122(亚美尼亚宗徒教会), 123(埃塞俄比亚正统台瓦西多教会), 124(厄立特里亚正统台瓦西多教会), 125(玛兰卡正统叙利亚教会)
```
与运行时日志 `14 / 上溯 0 / 未挂 8` 完全一致（含 8 个 id 逐个一致）。

**最小代码改法（未擅自修改，交 Lead 裁决）**：把 `GameWorld.Core.cs:1100` 的 `anchorDenom >= 0` 改为 `anchorDenom != -1`（或对 `-100000-range` 的合成 id 放行）。改完后，即便内容继续"faith 挂 faith"，兜底也能挂到默认宗派。
