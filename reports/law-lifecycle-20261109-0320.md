# 法律与习惯生命周期：设计落盘

> 2026-11-09 03:20（Asia/Shanghai）。用户口径：已知 → 推行中 → 生效 → 固化 → 宪法化（需革新）；无成文法时只有**习惯**，习惯在文化传统里；**习惯会变成法，法也会变成习惯**。

所以这次不是"重新设计"，是**把已经留好的槽位接上**。

## 2. 四阶段必须分开（这是最容易做糊的地方）

| 阶段 | 是什么问题 | 判据 | 玩家能感到什么 |
|---|---|---|---|
| **Pending 推行中** | 行政问题：命令要传下去 | `enactmentDays` + 合规度 | 面板"推行中"、可取消 |
| **Active 生效** | 执行问题：效果结算 | 到期未撤销 | 税/人力/稳定在变 |
| **Consolidated 固化** | 社会问题：反抗成本上升 | 连续生效 N 年 + 合规度 | 撤销代价变高、编年史"已成定制" |
| **Fundamentalized 宪法化** | 主权问题：谁能改它 | 革新 + **制宪主体** + 合法性阈值 | 同组普通法**不能覆盖**它 |

> 一句话：**Pending 是行政，Active 是执行，Consolidated 是社会，Fundamentalized 是主权。** 混成同一层，就会出现"点了按钮法就永久有效"这种假象。

## 3. 两座桥

**习惯 → 法**（三件齐备，缺一不成）：① 传统 `solidification` 达阈值（长期实践）；② 提出者位阶够（`TraditionElevation.Rank`：平民 0 / 廷臣 1 / 商人教士学者 2 / 贵族 3 / 君主 4，政治类传统有 `minRole` 门槛）；③ 政权有立法能力（`proposalAuthority` + 集权/财力/合法性）。生成 `normKind=Statute`、`source=custom`、`upgradesFrom=traditionId`。

**法 → 习惯**：某法连续 Active ≥N 年且合规度均值 ≥X → 写回传统（`solidification +=`，编年史"某法已成习俗"）。**关键：此后即使该法被 Repealed，习惯仍在**——"法死习惯活"才是常态。

## 4. 你的模型我认为还缺的八点

1. **失效不止废除**：还有被替代（replaced）、悬置（suspended）、**纸面法**（合规度极低 → 效果按比例衰减，而不是 100% 生效）。历史上"没废除但已死"是多数。
2. **法的层级与冲突**：宪法化只是最高位阶；还需上位/下位、特别法优先、后法优于前法、法不溯及既往。字段（`normKind/scope/precedence/overrides`）全在，**JSON 0 次使用、无读取点**。
3. **地域效力**：一法不必行天下（地方习惯、城市特许状、边疆特权）。`LegalScope` 有枚举，无消费者。
4. **人格效力**：贵族/教士/平民/外国人适用不同法——这正好接你刚定的**身份**轴（`SocialIdentityFlags`），目前零判定。
5. **判例作为第三法源**：司法链本该产生判例，现在整段空转。
6. **习惯的层级与冲突**：家族习惯 / 地方习惯 / 族群传统 / 宗教法，冲突时谁优先——这会让"传统"从装饰变成法源。
7. **宪法化的"谁"**：不只是"有革新"，还要有**制宪主体**（君主诏令 / 议会决议 / 教团裁定）；否则宪法化退化成"科技解锁"。
8. **政权断裂时的法**：政权灭亡后，继承国沿用？征服者废除？习惯残留？——这直接决定建国与读档的叙事一致性。

小点：**时效**（试行期、日落条款）可用 `enactmentDays` 的兄弟字段实现。

## 5. 验收信号（已写进 LAW_LIFECYCLE §5）

1. 习惯→法：solidification 够 + 位阶满足 → 出现可推行的 law；位阶不够 → 不出现。
2. 法→习惯：连续生效 + 合规 → 传统出现/固化度上升且有编年史；撤销该法后传统**仍在**。
3. 宪法化：无革新不可达；有革新+制宪主体+合法性可达；此后同组普通法无法覆盖。
4. 纸面法：合规度低 → 效果按比例衰减。
5. 层级冲突：普通法 vs 根本法 → 结果由 `precedence` 决定，有测试。
6. 人格效力：同一条法对贵族与外国人给出不同适用/豁免。
