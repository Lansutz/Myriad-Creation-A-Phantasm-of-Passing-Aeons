# P7 时间尺度、革新细化与世界细节计划

> 用户口径（2026-11-14）：100 年就出现政权太快；要更接近真实历史的周期；倍速要能到 30x；革新要更细致、覆盖所有系统；法令与对应革新要补；Azgaar 的城镇预览（含河流）要学；河流算法要找更好的；美术/地形材质要提上日程；板块漂移与河流洪水/改道要做，但必须有好优化与数据依据。
>
> 本计划是总计划；施工按阶段拆目标，不一次性吞完。

## 1. 阶段

### P7.0 时间尺度与倍速（先做，影响所有系统）

- 倍速：1x/2x/5x/10x/30x；`GameManager` 钳 0–30；UI 用“速度”循环按钮/菜单暴露五档（不改场景文件，运行时创建）。
- 自然建国周期：`MinSettlementAgeYears` 8 → **200**；人口 200 → **800**；开发 6 → **15**；口粮剩余 90 → **180 天**。这是“世界尺度默认”，不是历史定律，后续可外提为内容。
- 验收：
  - 100 年默认自然世界**不出现政权**（防回退到“开局即国家”）；
  - 220 年自然长跑出现政权/官职/实物税流水；
  - 五档倍速都能设置且 UI 标签同步；`Time.timeScale` 不超过 30。
- 风险：30x 下 UI/动画/事件队列压力；用 `unscaledDeltaTime` 的 UI 不受影响，事件队列按 tick 处理。

### P7.1 革新细化 + 法令补齐（研究驱动，工作量大）

> 用户追加（2026-11-14）：目前革新数量太少；城市出现周期偏短与革新/研究速度有关，需要一并调整革新研究（速度、前置、传播）。
> P7.0 的 200 年建国门槛是硬门禁；P7.1 要把“为什么这个社会还没到能建国的技术/制度阶段”也做成革新与法令条件，而不是只看人口。

- 先做**覆盖矩阵**：按系统（农业/畜牧/渔业/采矿/冶金/工艺/建筑/运输/军事/行政/法律/财政/文字/宗教/医学/天文/生态）列出已有革新、缺失环节、对应法令/建筑/配方/阶层。
- 历史依据：新石器—青铜—铁器—古典—中世纪的技术/制度时间线，参考考古与制度史（农业起源、灌溉、轮子、冶铁、文字、法典、官僚制、常备军、行会、银行等）。只取“机制含义”，不照搬某文明。
- 每条新革新必须有：物质前提（资源/工具/建筑/人口）、传播条件、可观察效果（解锁配方/建筑/法律/兵种/行政容量）、可失败/可回退。
- 法令：每个法域补“对应革新门槛 + 执行机构 + 成本/维护 + 违宪/阻力”，不再只加 `taxMultiplier` 数值。
- 验收：覆盖矩阵无“只有枚举没有消费者”的革新；新增条目走 Base JSON + Mods 覆盖；法律与革新有交叉引用测试。

### P7.2 河流算法、洪水与改道（研究 + 优化）

- 先对比：现有 D8；Azgaar 的 priority-flood + 降水汇流 + 流量阈值 + 蜿蜒；可选方案：Barnes priority-flood、D-infinity、RichDEM/Landlab 类方法。
- 目标：
  - 河宽/流量/等级由汇水面积与降水推导，不是阈值二值；
  - 蜿蜒/曲流（几何，不改拓扑）；
  - 湖泊/三角洲/入海口；
  - 洪水：按气候（暴雨/融雪）+ 地形（谷地/洪泛平原）+ 河道容量判定，不是全河随机；
  - 改道：只在泛滥平原/低坡度/高含沙河段，按确定性概率与历史洪水累积触发；不是所有河流都改道。
- 数据：收集河流洪水/改道频率、河道容量、泥沙、气候因子的经验范围，写进内容表（可 Mod 覆盖）。
- 性能：河流/洪水只跑 dirty 河段/洪泛区；年/季 tick，不每日全图。

### P7.3 城镇预览（Azgaar/Watabou 参数语义 → 本地布局）

- 扩展 `CityLayoutPlan`：河流折线（来自 HydrologySystem）、海岸线、农田、城墙、市场、神庙、广场、贫民区、桥梁。
- `CityLayoutRenderer`：把河流/海岸画进俯视图；布局按 `river/coast/farms/walls/temple/plaza/size/population/seed` 参数确定性生成。
- `CityViewPanel`：显示“城镇预览”，可缩放/平移；无河流/无城墙是合法状态。
- 数据来源：聚落 `isCoast/isPort`、地块 `isRiver`、`hasMarket/hasTemple`、`walls`、人口、地形。
- 验收：同一聚落同 seed 同图；河流/海岸改变布局；无河聚落不画河；纹理缓存 LRU 不回归。

### P7.4 地形材质与美术管线

- 地形材质分层：基岩/土壤/植被/雪线/湿地/沙漠/河流/海岸，法线/粗糙度/颜色随气候与群系变化；不再是单色/粗糙拼贴。
- 地图风格与 `CyowariHistoricalMap.shader` 对齐；先做可替换的材质参数表（JSON/ScriptableObject），再做贴图。
- 验收：同一地图在不同群系/气候下颜色/粗糙度可区分；材质参数可 Mod 覆盖；性能不超预算。

### P7.5 板块漂移与长期地质/气候（最后做）

- 生成期：板块边界、造山/裂谷/热点；运行时：极慢 tick（10/100/1000 年压缩），只更新构造应力/海平面/侵蚀/沉积/河流改道。
- 数据：板块速度、造山速率、海平面变化、侵蚀速率；全部内容表 + 可关闭。
- 性能：长期 tick 只跑区域聚合与 dirty 河段；默认关闭/低频，避免每帧。

## 4. P7.0 施工记录（2026-11-14）

### 4.1 时间尺度与倍速

- 新增 `GameSpeedScale`（`MyriadCreation.App.Contracts`）：五档 `{1,2,5,10,30}`、暂停 0、上限 30，`Clamp/IndexOf/Next` 单源。
- `GameManager.SetGameSpeed` 走 `GameSpeedScale.Clamp`；`UIManager` 的 TopBar 循环按钮同样从该表单源取档位，标签按真实速度显示（非五档值显示实际值，下一次点击从 1x 起循环）。
- 场景旧 1x/2x/3x 按钮保留引用但运行时隐藏，不改场景文件。
- 测试：`GameSpeedScaleTests`（档位升序且末档=上限、超 30 钳制、负值按暂停、循环回绕、旧 3x/暂停从 1x 起）。

### 4.2 自然建国周期

- `StateFormationSystem`：聚落年龄 ≥200 年、人口 ≥800、开发 ≥15、地区仓储 ≥180 天口粮；每月最多一个，`MaxRealms=8`。

### 4.3 长跑暴露的四个底层机制缺陷（逐个修复）

1. **世界气温公式把陆地海拔重复罚了一次**：`ComputeBaseAnnualTemperature` 用全表归一化高程 × 65℃，陆地平均高程约 0.5，等于每块地再罚 30℃；48×24 默认世界均温 -28.7℃、164/329 块陆地是冰盖、肥力中位数 0.03。
   - 改为“相对海平面的陆地高程 × 45℃”，并新增 `LandElevationAboveSea`；破碎化补算统一传当前（已相对化）的 `elevation01`。
   - 修复后均温 -0.2℃，冰盖 76 块，肥力 p50=0.08 / p90=0.50 / max=0.87。
2. **承载力与农业产出口径不一致**：承载力只看地形/NPP/开发，贫瘠沙地也能算出几百人；现在加入与产出相同的肥力乘子 `(0.2+0.8×肥力)`，基准 1500、开发乘子 `0.45+0.55×开发`。
3. **人口过载只会把增长率压到 0**：改为超出承载后的马尔萨斯净减少（饥荒/疫病/迁出），避免人口卡在承载线上反复过冲再饿死。
4. **肥力只减不增**：`EcosystemSystem.Tick` 每月把肥力向气候/地形潜在值拉近 1%（约 5–6 年恢复一半），只向上靠拢；灾害日损下调到可被恢复配平（旱 -0.0002、蝗 -0.001、歉收 -0.0005）；`SwarmAI` 改为“到达新地块才结算一次”，不再按日原地扣（原 -2.0 在 0–1 尺度下等于一次清零）。
5. **聚落选址不看地力**：省治聚落改为省域内“肥力×NPP×水”得分最高地块，额外村落从地力前 1/3 抽取，初始人口按选址得分给（300+900×score），不再把两千人塞进干旱海岸。
6. **营地演化成聚落的空引用**：`SettlementEvolutionSystem.TryEvolveCampToSettlement` 直接写 `settlementData.fortifiedOutpostData.purpose`，而新建 `SettlementData` 的模式数据按默认 SiteMode 初始化、据点数据为 null；长跑中首次演化即 NRE。已加空值守卫。

### 4.4 农业校准

- `AgricultureYield.OutputPerFarmerPerDay` 0.03 → 0.045：旧值只能“农夫自养”，社会一旦分化出商人/贵族就全城净缺粮；新值在中等土地上 1 农夫供养约 1.5 人。
- `SocialClass.Slave` 计入农业劳动力（前现代奴隶普遍下地），不再只数 Peasant。
- 测试：`SoilRecoveryTests`（退化土恢复/不超潜在值/火山增肥不被抹掉/恢复后产出提高）、`SwarmDamageTests`（每地块只结算一次、单次过境不清零）。

### 4.5 长跑继续暴露的消费/人口链缺陷（第二批）

7. **人口增长被自己覆盖**：`PopulationTick` 先 `PopulationLedger.Scale` 改列表，随后又把 tick 开始时复制的旧 `PopulationBlock` 写回，增长每次都被抹掉。改为“先写满意度、再缩放”。
8. **可食货清单为空**：内容表加载顺序使 `_edibleGoods` 为 0，消费链静默失效；同时 `ProcessConsumption` 仍对每块地扣“饥荒稳定度”，把全图稳定度/满意度永久压到 0。修法：惰性重建可食货列表、兜底商品表显式 `MarkEdible`、无任何可食货定义时跳过消费而不是判定全图饥荒。
9. **饥荒口径与消费不一致**：饥荒只统计写死的 `{0,1,2,10}`，粟/黍等 edible 货不算，出现“粮仓满但判饥荒”。改为统一使用经济系统的 `EdibleGoods` 清单并按营养折算，空表时回退旧常量。
10. **稳定度只减不增**：一次饥荒的 −10 永久生效，满意度随之归零、增长率腰斩。`EcosystemSystem` 每月把稳定/秩序向 50 恢复（约 4 年）。
11. **文化渗透 0 被当作极低值**：新人口块 `culturePenetration=0` 每日扣 −0.25 满意度；改为 ≤0 视为未初始化、按中性 50 处理。
12. **粮食存不住**：小麦 180 天、稻/粟/黍 365 天的储存期意味着每天 0.3%–0.6% 损耗，盈余永远存不下来；把主粮储存期改为 1800 天（约 5 年）。
13. **贸易把本地口粮抽干**：出口只保留 30 天口粮，产粮城被自家商队抽到饥荒线；出口储备改为 180 天（含种子与青黄不接），与建国余粮门槛同口径。
14. **承载力与单产不同口径**：改为 `2400 × 土地质量`（地形 × NPP × 开发 × 肥力），中等土地约 800–900、贫瘠地 200–300；农业单产 `0.05/农夫/日`。
15. **迁移一次搬走 10% 全城**：改为只迁出“超出承载 1.1 倍的部分”，每次最多 2%，避免过载城市几个月被搬空。
16. **人口自然增长 73%/年**：`0.002/日` 改为 `0.00003/日`（约 1%/年），前现代量级；避免人口一年冲满承载力后靠饥荒回落。


### P7.6 仓储设施与设施升级（用户 2026-11-14 追加）

- **仓储容量由设施决定，不再由常数 10000 决定**：粮仓（谷物）、盐仓/冷窖（易腐）、金库（货币/贵重）、普通货栈（矿料/木材/工艺）分别提供容量；没有对应设施就没有对应仓储。
- 设施是可升级建筑：每级提供容量/保鲜/损耗减免；升级消耗材料与工时，材料走现有 `RecipeCatalog` 合成链（木材/石料/工具/铁件），并受革新解锁。
- 贸易/征税/饥荒判定都读“该地区实际仓储容量”，而不是 `TradeCenter.inventoryCapacity` 的硬编码。
- 验收：新地区默认只有小型货栈；建粮仓后粮食容量上升；升级消耗真实材料且可失败/可回退；无粮仓地区不能无限囤粮。
