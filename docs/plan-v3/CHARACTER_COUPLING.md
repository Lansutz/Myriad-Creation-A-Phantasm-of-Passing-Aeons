# 角色耦合层：用人物互动吸收系统耦合（v1）

> 用户口径：模拟要**尽量**真实，但不能因"系统耦合暴露给玩家"而变得复杂、信息量大；**这个问题由角色系统解决**——不扮演国家意志，有多种视角，很多事不需要玩家亲自去办。
> 定位：`INTEGRATION_PLAN.md`（耦合矩阵 / 六问门禁 / WP1–WP6）的下游设计件；服从 `DECISIONS.md` D15（人物为体）、D17（视角≠模式）、D32（Plan 改成结构语义 + 内容定义）。
> 四条质量轴必须同时成立：**真实**（人物承担复杂度）/ **性能**（事件驱动，不轮询）/ **可维护**（新增一种事 = 加内容）/ **可模组**（JSON 驱动）。任一条不成立即打回。
> 数值纪律：税率 / 比例 / 阈值**不得硬编**——要么给出处（如什一税 = 教会惯例 1/10，须带文献锚点），要么标「待标定」。

---

## 0. 一句话原理

**系统耦合没有消失，它被转移到人物的行动背后。** 玩家面对的是"某人在办某事"，不是"某个面板在调参"；耦合复杂度由受任者的 AI 承担，而不是由玩家的注意力承担。

| 段 | 机制 | 代码落点（已核） | 现状 |
|---|---|---|---|
| ① **授权** | 统治者授官职 / 头衔 / 特许权 | `RealmData.officeHolders`（officeId→characterId）、`TitleInstanceRegistry` | 在跑；但 `ActionIds.AppointTitle` **零使用者**，开局 0 官职 |
| ② **代理** | 受任者按自己的 AI 决定"怎么办" | `CharacterAICategory` 12 类（`CharacterAICategory.cs`） | **只是标签**：`.aiCategory` 全部命中为赋值 / 存档 / 商队判定（`MapActor.cs:276,306`），无 Think/Act 分派 |
| ③ **执行** | 委托变成有时长、可中断的过程 | `Plan`（`initiatorId/ownerId/participants/requirements/waitCondition`，`Plan.cs`） | 框架完整，10 类里只有 Research 在转（`SYSTEM_MASTER_PLAN` §3） |
| ④ **结果** | 结算仍在系统层，**归属到人** | `PoliticsSimulationSystem.cs:86-87`（税→treasury）、`SettlementBlock`（工程） | 在跑，但无"谁办的"字段（D31 已定 `builderCharacterId`，尚无生产调用） |
| ⑤ **追责** | 失败落在具体人身上 | 事件 + 关系值 + 官职撤销 + 编年史 | 待建 |

**它不能替代什么**（这三类必须留在系统层，理由是"它们是分母，不是意志"）：

| 必须留在系统层 | 理由 | 若交给人物会怎样 |
|---|---|---|
| **守恒类结算**（物资/货币/人口/伤亡） | 同一事实不能有两个版本；单个角色看不到全局账本 | 制造第 7 组双真源（已有 6 组，见总纲 §4.4） |
| **对抗性结算**（战争、审判对抗、密谋对抗） | 需双方同时在场、独立于任一方知情 | 谁先算谁赢；玩家可反复问数探知对手底牌 |
| **时间与传播的中枢推进**（命令延迟、消息扩散） | 必须按日单向推进，不能各角色各算一套 | 时序不可复现，存档读回不一致 |

> 换言之：**人物决定"做不做、怎么做、做到什么程度"；系统决定"做了之后账怎么平"。** 玩家感到复杂的那一层（参数、乘子、账本）留在系统层但不进玩家视线；玩家视线里只有人和后果。

## 1. "玩家不需要亲自办"的落地：七类委托

统一形态：玩家（或其视角人物）**授权** → 受任者以自己的 AI 发起 `Plan` → 系统结算 → 事件/关系/编年史回流。
`Plan.initiatorId` = **受任者**（"谁办的"）；授权人另存（新增 `grantedByCharacterId`，见 §6 第 4 项），二者必须分开——否则追责追不到人。

| # | 场景 | 谁执行 | 授权形式 | 玩家默认看到什么 | 失败如何反馈到玩家 |
|---|---|---|---|---|---|
| 1 | **建造**（城墙/粮仓/道路） | 地方官或受任工程主持 | 官职 / 一次性委任状 | 地图上多出一段工程，**署名是某人本名**（D31）；进度条只给区间 | 超期 / 材料被挪用 / 质量低（等级低于申报）→ 事件「某人的工程延期」+ 对其好感下降 |
| 2 | **征税** | 税吏（aiCategory=Official） | 包税 / 代征官职 | 国库增量（L0）+ 税吏**口头汇报的实收数**（L1，可能虚报） | 实收与应征的差额被截留 → 你可召见问数、可查账、可撤职；差额不自动出现在 UI |
| 3 | **征兵** | 地方军事长官 | 军职 + 征募配额 | 兵额与兵质（区间），**延迟到集结时才看清** | 兵额不足 / 新兵占比高 / 拖延 → 战争开局战力低于预期，追责在战后 |
| 4 | **立法推行** | 各级官员（逐级下达） | 官职默认职权（非法令本身） | 法律在中央生效（L0），地方**合规度**只是趋势 | 地方不执行（合规度 <1）→ 纸面法；表现为税收/征募不达预期，而非弹窗 |
| 5 | **审判** | 法官 / 领主法庭 | 司法职权 | 案件结果 + 民心变化（L0） | 判错 / 受贿 / 激起民愤 → unrest 上升、相关阶层好感下降、编年史留恶名 |
| 6 | **传教** | 教士 / 修会（S18 非独立组织模型） | 教职 / 特许状 | 人口信仰构成缓慢变化（L0 滞后） | 被当地抵制 / 传成异端 / 停滞 → 教派冲突事件、正统性争议；责任落到该教士与批准者 |
| 7 | **外交使团** | 使节（aiCategory=Courier 已有，`GameWorld.Simulation.cs:697`） | 临时委任 + 谈判授权范围 | 条约文本与结果（L0），过程不可见 | 条件被私自放宽 / 被收买 / 被扣押 → 不利条款、使节死亡或叛变；`DiplomacyManager` 已是真源（D32 已删 Diplomacy PlanType） |

**判据（防止把系统层该做的事塞进委托）**：一件事只有在"**由谁办会得到不同结果**"时才值得做成委托；若换成谁都一样，它属于系统结算，不进本表。

## 2. 授权链的成本模型（否则"授权"＝免费外包）

| 成本项 | 谁承担 | 机制落点 | 现状 |
|---|---|---|---|
| **财货** | 授权者预付（国库/领主私产）；受任者垫付可报销 | `Plan.requirements` + `RealmTreasuryProvider`（四层门禁已有，但当前只拦 `declare_war`） | 门禁在，未接委托 |
| **时间** | 受任者（一人同时在办几件事有上限） | `CharacterData` **无日程/在办数**字段 → 待建 `activeDelegationCount` + 容量 | 待建；容量值**待标定** |
| **政治** | 授权者（授权即让权） | `RealmData.centralization` 下调 | 字段在，无授权侧写入 |
| **风险** | 失败时**受任者**损失威望/官职/好感/私产；**授权者**承担合法性/稳定度的折扣部分 k | 事件 + 关系值 + `officeHolders` 移除 | 待建；k **待标定**（先给区间 0.1–0.3，M0.5 校准） |
| **追责** | 三级：斥责 → 罚金 → 撤职 | 关系值 + 官职移除 + 编年史条目 | 待建（`ActionIds.AppointTitle` 现零使用者，撤职同理） |

**三道闸门（缺一即为免费外包，不得进内容表）**：① 授权有**预付成本**；② 受任者**能力不足就办不成**（能力必须进判定，不能只进描述——呼应 D21「差异进入决策」）；③ 受任者**有自己的目标**（可拖延、可挪用、可顺手办成自己的事）。第 ③ 条是真实性的来源，也是复杂度的唯一来源——它被关在 NPC 内部，不进玩家 UI。

**热路径禁令（性能）**：不得"每个角色每月评估所有委托"。委托只由 `PlanStateChanged`（`PlanSystem.cs:29-37` 已有 5 个事件）驱动；`characters.daily` 已是全表 O(N) 循环（`CharacterManager.cs:1001-1006`），其中**禁止**新增对委托表的扫描；查询走 `delegationIndex[characterId] → planIds` 的 O(1) 旁路索引。

## 3. 信息量控制：可见性四级

| 级 | 玩家如何获得 | 典型内容 | 设计要点 | 现状 |
|---|---|---|---|---|
| **L0 公开事实** | 直接看（地图/面板） | 在位者、聚落规模、战争状态、法律是否生效、工程**署名**、信仰构成 | 玩家**不点开也知道世界在变** | 聚落详情面板在跑；编年史**数据在写、界面不可达**（总纲 §0）；地图点选空实现 |
| **L1 需问人** | 主动动作「召见/问话/查账」 | 工程真实进度、税额实收、征兵实数、他省民情 | 回报**带误差区间**，误差来自受任者能力与忠诚；问得越多，人对你越不耐 | **待建（WP4 信息传播）** |
| **L2 需职位/亲信/情报** | 有对应官职或亲信网络才解锁 | 他国意图、密谋、腐败、教义争议内情 | 换视角才看得到（见 §4）；缺信息本身就是玩法 | 待建（WP5 Intrigue、S17 消费者为零） |
| **L3 永不可见** | 无（事后编年史可留痕） | 他人私下决定、被销毁的记录、自己死后的事 | 保证"世界有玩家不知道的部分"，但不影响可玩性 | 天然成立 |

**关键取舍**：把"精确数字"从 L0 全部下移到 L1/L2。玩家看到的是**人与后果**（谁办的、办成没办成），而不是别人账本上的乘子。这条是"信息量控制"的核心动作，比藏面板更有效。

## 4. 多视角如何降低耦合成本（一个模拟、一套存档，D17）

同一 tick、同一份状态，不同视角只是**不同的查询切片 + 不同的可下动词集合**。于是 UI 量级 = 视角数 × 薄视图，而不是系统数²。

| 视角 | 能下的令（本人职权内） | 看到的"系统" | 默认看不见（L2/L3） | 底层不变的部分 |
|---|---|---|---|---|
| **君主** | 授权/撤职、立法、宣战与和约、指定继承 | 国库总量、政策效果趋势、臣属忠诚区间 | 某村的收成、某商人的账本、地方官的私下交易 | `PoliticsSimulationSystem` + Laws + Warfare |
| **地方官** | 委任工程、征发、审判、请托传教 | 本辖区人口/产能/实收税额、水利与道路状态 | 全国财政、他省军力、朝廷派系斗争 | Settlement + Construction Plan + Justice |
| **商人** | 开路线、雇护卫、借贷、行贿（非法但存在） | 价格、库存、路线效率、风险与延误 | 官职任免、教义争论（除影响市场） | `EconomyManager`（纯自动经济，现状即如此） |

**成本下降的机制**：每个视角只暴露"该人物有权感知 + 有权处置"的那一小块耦合面；系统间真实的机制嵌套（教义→婚姻→继承→税基）**照旧发生**，只是不要求玩家同时理解。

## 5. 反向约束：必须本人拍板的事（否则没有张力）

| 决定 | 为什么不能委托 | 门禁写法 |
|---|---|---|
| **战争 / 和约** | 一旦可委托，玩家失去"代价由我承担"的重量 | `ActionGate` 只接受 `HeadOfState/CoRuler`，且 `delegable:false` |
| **继承指定**（heir） | 指定必须本人；**执行**可被摄政/篡改——这才是历史 | 指定入 `RealmData.heirId`；篡改走密谋，不走进合法入口 |
| **根本法 / 宪法化** | `LegalNormStage.Fundamentalized` 的正当性来自统治者签发 | 必须有统治者签署 + 程序，缺一不可（见 `LAW_LIFECYCLE.md`） |
| **授权本身** | 不可无限转委托 | `maxChainDepth`（建议 2，**待标定**）；超限即 `not_authorized` |
| **视角人物本人的不可逆选择**（改宗、婚配、退位） | 这是"角色"而非"政权"的决定，必须由该人物（=玩家此刻）做 | 走个人层 `privateFaithId` / `Marry`，不经官职代理 |

## 7. 验收（可执行断言）

1. **A1 张力**：新局中玩家全程不授权 vs 全部授给称职受任者，第 3 年聚落产出/税入差异 ≥ X%（X **待标定**，先按 15–30% 区间做对照跑，M0.5 定值）。
2. **A2 无静默失败**：内容表遍历测试——每个 `DelegationDef` 的 `failureCodes[]` 非空，且每个码都有事件/UI 文案映射；出现"失败但玩家无从知晓"即红。
3. **A3 表驱动**：EditMode 测试——删除 `Titles.json` 中某 office 的 `authorityGrants` 条目，该持有者调用对应动作返回 `GateResult.Denied(Authority, "not_authorized")`；改回即恢复。
4. **A4 性能**：100 年跑（M0.5 验收台）日耗时增量 ≤ 门禁；插桩断言 `characters.daily` 内无对委托表的全表扫描；委托推进次数 ≈ `PlanStateChanged` 次数。
5. **A5 视角切片**：同一日、同一存档，君主/地方官/商人三视角各自查询返回的字段集**互不越界**（不得出现地方官读到全国财政）；UI 只经查询契约取数（硬边界测试）。
