# 审计输出格式（所有域共用，必须逐条遵守）

> 目的：让 8 份域审计可以被合成成一份总纲，且每句话都能被 Lead 复核。

## 硬规则

1. **只读**：不得修改任何 `.cs` / `.json` / `.unity` / `.prefab`。只允许写你自己的那一份 `docs/plan-v3/audit/<域>.md`。
2. **代码是唯一真源**。`docs/**` 与代码冲突时以代码为准，且**不得把文档自述当证据**（可以写"文档称 X，代码实为 Y"，但证据必须是代码）。
3. **每条结论必须带证据锚点**：`路径:行号`（相对 `MyriadCreation/`，例如 `Assets/Scripts/Simulation/.../GameWorld.Simulation.cs:812`）。grep 计数必须附命令与命中数。
4. **三态判定**，不得含糊：
   - `在跑` = ①主循环 tick（`GameWorld.Simulation.cs` 注册）或在真实调用链上被调用；②有玩家 UI 入口 **或** AI/规则自动驱动；③状态入档（SaveSystem 往返）。
   - `半跑` = 只满足其中 1–2 条 → 必须写清**缺哪一条**。
   - `空转` = 有类型/字段/方法但零调用者（附 grep 证据）。
   - `不存在` = 连数据模型都没有。
5. **区分"有定义"与"有消费者"**：定义（`class/struct/field`）不算功能；必须指到"谁读它、谁写它、结果影响哪个可观察量"。
6. **禁止写方案**：不要写"建议改成…"。只写事实与缺口。方案由 Lead 在总纲中裁决。
7. **控制体量**：≤ 220 行。宁可少写系统，也不要把"没查到"写成"已经好了"。

## 必填骨架

```markdown
# <域> 审计（<日期>）

## 0. 范围
- 读取的文件/目录（列全，含行数规模）
- 未覆盖的部分（明确写出，别假装覆盖了）

## 1. 系统清单
| 系统 | 三态 | 驱动证据（file:line） | 入口证据 | 存档证据 | 测试 | 一句话现状 |

## 2. 数据模型现状
（关键类型/字段，哪些字段有生产者/消费者，哪些是"承诺未兑现"的字段）

## 3. 内容数据现状
（对应 `StreamingAssets/Base/<域>` 的条目数、被代码引用的比例；用 grep/JSON 解析计数）

## 4. 缺口清单（按影响排序）
| # | 缺口 | 影响 | 证据 | 严重度(P0/P1/P2) |

## 5. 我核实不了的事
（明确列出，别猜）
```

## 三态判定速查（本项目已验证过的坑）

- **测试全绿 ≠ 功能可用**：法律系统 703 个测试全绿，但革新门槛实参恒为 `null`（`LawContracts.cs` 修复前）。
- **有 DTO 字段 ≠ 已入档**：DTO 存在但 Adapter 没写 = 存档丢数据。
- **`Register(...)` 注册 ≠ 有效**：注册了但内部恒早退（如 `justice.daily` 因字典恒空）也算空转。
- **UI 文件存在 ≠ 有面板**：`Assets/UI/Panels` 只有 6 个面板，凡不在其中的系统，玩家入口大概率为 0。
