# 现有革新对照与去重审计（Innovation Dedupe Audit）

> 用户问："这些东西有查过现有的革新吗？道路铺设、桥梁建造，什么桥梁什么道路？桥梁道路可大了。石灰石、混凝土、大理石？"
> 结论：**查过，而且发现上一版候选池确实与现有 185 条重复/粒度不当**。新增前必须先做"复用 / 改名 / 拆分 / 转为物产"四选一。
> 本文只做审计与细化，不改代码。

---

## 1. 审计方法

对每条候选走一遍：

1. 现有目录里是否已有同义/近义条目？→ **复用或改名**，不新增。
2. 现有条目是否把"物产/器物/宽泛活动"当成了革新？→ **拆分/降级**。
3. 新条目是否比现有条目更具体、且能改变模拟变量？→ 才新增。
4. 只是材料/器物/建筑名称？→ 进 `GoodsDef`/`EquipmentDef`/`BuildingDef`，不是革新。

## 3. 道路：按"路面/工程"拆，不叫"道路铺设"

现有 `808 硬质道路` 太宽。拆为：

| 建议条目 | 说明 | 前置/复用 |
|---|---|---|
| 夯土道路 | 压实土路面，雨季易坏 | 复用 808 基础 |
| 碎石路面 | 碎石+压实（macadam 式），排水好 | 808 |
| 铺石路面 | 石板/石块铺砌，重载/城市 | 808 + 采石/石材加工 |
| 木栈道/木排路 | 沼泽/湿地/森林 | 808 + 木工 |
| 堤道 | 跨低洼/湿地，垫高路基 | 808 + 土方工程 |
| 道路网/驿道 | 路线与维护制度，不是路面技术 | 823 驿传 + 808（制度/网络） |

> "道路"本身是**基础设施**；`道路网` 是制度/网络；`路面技术` 才是革新。三者分开。

## 4. 桥梁：按"结构/材料/跨度"拆，不叫"桥梁建造"

现有 `801 拱券技术` 是石拱桥的基础，但没有桥型条目。拆为：

| 建议条目 | 说明 | 前置 |
|---|---|---|
| 木梁桥 | 短跨、木梁/木柱 | 木工 |
| 石拱桥 | 石砌拱，跨中等河流 | 801 拱券 + 石材加工 |
| 浮桥 | 舟/筏串联，军用/临时 | 造船/木工 |
| 吊桥/索桥 | 藤/竹/铁索，跨峡谷 | 绳索/冶金（按材料） |
| 栈桥/木架桥 | 高架木结构，跨湿地/谷地 | 木工 |
| 桁架桥 | 近代木/铁桁架，大跨 | 木工/冶金 + 结构知识 |

> `桥梁建造` 太宽，不能作为一条；`石拱桥` 与 `木梁桥` 的模拟效果（跨度、载重、成本、维护）不同。

## 7. 修正后的新增原则

1. 先查现有目录；有同义/近义 → 复用/改名/拆分，不新增。
2. 材料/器物/宽泛活动 → Goods/Equipment/Building，不是革新。
3. 新增只用于：现有目录没有、且能改变模拟变量的**具体能力**。
4. 首批 150–250 条是**能力条目**，不是物产/材料清单；物产另表。
5. 每条新增必须写 `reusesExistingId`（若有）或 `newReason`。

## 8. 与现有系统的落点（按代码写，不按印象）

### 8.1 城墙：Block + 材质 + 形制 + 横向段/层 + **城防等级 0–15**

> **实现状态（2026-11-03）**：已落地 `WallMaterial` / `WallSegment` / `FortificationLevels`，`WallDefense` 已聚合多块+段，`wallLayerCount` clamp 1–3，旧档 `wallDataVersion` 映射；测试 `WallFortificationTests` 8 条，全量 EditMode 606/606。

实测：

- `BuildingDef` 只有 `buildingId/name/category/tier/buildCost/materialCost/buildDays/maintenanceCost`，没有墙体类型。
- 城墙是聚落块：`SettlementBlockKind.Wall`，子类型 `WallSegment/Gate/Tower/Moat/Palisade/Earthwork/Keep`。
- 现有 `WallLevel`：`Palisade / EarthenRampart / StoneWall / FortifiedWall / StarFortification / MegaFortification`，**把材质、形制、防御等级混在一起了**。
- `WallLayout`（Straight/Ring/Polygonal/MultiCircuit）、`wallLayerCount`、`wallMoatLevel`、`WallRole`（Primary/Inner/Outer/Extension/Palace）已经存在。
- 多个城墙块：`SettlementData.GetBlocks(SettlementBlockKind.Wall)` 返回列表，`GetPrimaryWall()` 按 `WallRole.Primary` 取主墙，说明**数据/存档层支持一个聚落多个城墙块**；但 `WallDefense.Evaluate` 只调用 `GetBlock` 取一个，`EnsureRootBlock` 也只建一个根块——**支持不完整**。
- `wallLayerCount` 没有上限；用户要求最高 3 层，需要 clamp。
- "段"：`SettlementBlock` 只有总 `length`，没有横向段列表；`children` 可放 `WallSegment` 子块，但 `WallDefense` 不统计。需要补 `segments`。

#### 拆分模型

| 轴 | 字段/枚举 | 说明 |
|---|---|---|
| **材质** | `WallMaterial`：Palisade（木栅）/ Earth（夯土）/ Stone（石砌）/ Brick（砖砌）/ Composite（石面土心等） | 墙是什么做的 |
| **材质工艺** | `WallMaterialGrade` 1–3（粗制/标准/精制） | 同一种材质三档；影响耐久/成本/防御 |
| **形制** | `WallLayout`：Straight/Ring/Polygonal/MultiCircuit；`CityForm` 另管城市轮廓 | 墙怎么围 |
| **横向段** | `WallSegment` 列表（段长/现状/塔楼/城门） | 一座墙沿长度方向的横向分段；不是"多个城墙块" |
| **层** | `wallLayerCount` 1–3 + `WallRole`（Primary/Inner/Outer/Extension/Palace） | 一个城墙块最多三层；一个聚落可有多个城墙块（内城/外城等） |
| **城防等级** | `FortificationLevel` 0–15（由原 `WallLevel` 改名） | 综合防御等级；由 tier × 材质工艺推出 |

#### 城防等级 0–15：5 个 tier × 3 档材质工艺

| tier | 等级区间 | 含义 | 典型 |
|---|---|---|---|
| 0 | 0 | 无城防 | — |
| 1 | 1–3 | 简易围护 | 木栅/土垒；Palisade/Earthwork |
| 2 | 4–6 | 连续墙体 | 夯土/石/砖墙 |
| 3 | 7–9 | 设防墙体 | 墙体 + 城门/塔楼/护城河 |
| 4 | 10–12 | 棱堡/多面堡 | 星形/多边形棱堡 |
| 5 | 13–15 | 多重防线/巨型要塞 | 内外多道墙 + 堡垒群 |

- `FortificationLevel = (tier - 1) * 3 + materialGrade`（tier 1–5，grade 1–3），最高 **15**。
- 同一种材质有 **3 档工艺**（粗/标准/精），这就是"一种材质三个"；它不等于城防等级。
- `WallLevel` 改名 `FortificationLevel`；旧档映射建议：None=0、Palisade=1、EarthenRampart=4、StoneWall=5、FortifiedWall=7、StarFortification=10、MegaFortification=13（后续可平滑迁移）。
- `WallDefense` 必须用 `WallMaterial + Grade + tier/level + 塔楼/护城河/层数 + 所有城墙块 + 所有横向段` 聚合计算，而不是只看一个 `settlement.fortification`。
- `SettlementTypologySystem` 的自动抬墙改为条件式：聚落等级/资源/工程能力/革新满足才允许升级，不能 III 级自动土墙、IV 级自动石墙。

#### 多个城墙块 vs 横向段 vs 层

- **多个城墙块**：一个聚落可以有多个 `SettlementBlockKind.Wall`（内城/外城/卫城/延伸墙），用 `WallRole` 区分；数据结构有 `GetBlocks/GetPrimaryWall`，但 `WallDefense`/创建逻辑要补齐。
- **横向段**：一个城墙块内部沿长度拆的段（`WallSegment`），每段有 `length/condition/塔楼/城门`；总长度=各段之和；这不是"多个城墙块"。
- **层**：一个城墙块最多 3 层（`wallLayerCount` clamp 1–3），不是"聚落里三圈墙"；三圈墙是三个城墙块。

#### 多重城墙要不要单独革新？

**不建议单独一条革新。** "多重城墙"是**多个城墙块 + MultiCircuit 布局**，不是独立技术；用 `FortificationLevel ≥ 13` + `筑城规划/要塞工程` + 资源/人口门槛解锁布局即可。若以后要表现独特工程知识，可做 `InnovationVariant`/工程实践。

#### 革新 → 城墙落点

| 革新 | 落点 |
|---|---|
| `夯土版筑`（复用 800 改名） | `WallMaterial.Earth`，Grade 1–2；tier 1–2 |
| `石砌墙体`（新） | `WallMaterial.Stone`，Grade 1–2；tier 2–3 |
| `砖砌墙体`（新） | `WallMaterial.Brick`，Grade 1–2；tier 2–3 |
| `城门与塔楼`（新） | `WallSegment` 的 Gate/Tower；tier ≥3 |
| `护城河`（新） | `SettlementBlockSubtype.Moat` + `wallMoatLevel` |
| `棱堡`（新） | tier 4（等级 10–12）+ `WallLayout.Polygonal/Star` |
| `多重城墙` | **不设革新**；tier 5（等级 13–15）+ 工程能力解锁 `MultiCircuit` + 多个城墙块 |
| `拱券结构`（复用 801 改名） | 城门/石桥/拱顶；不是墙等级 |
| `城堡建筑`（复用 306） | `Keep`/设防墙体；tier 3 |

### 8.2 战车：现有 1013 已经是"双马战车"，不是"战车制造"

实测：

- `UnitDef` 字段：`unitId/name/category/GameEnums.UnitArmType/tier/melee/ranged/defense/morale/speed/supply/manpower/terrainModifiers/requiredInnovations`，**没有挽马数量/车辆类型字段**。
- 单位 210 `战车兵`，`UnitArmType.Cavalry`，`requiredInnovations = [1013]`。
- `1013 战车` 的描述已经是 **"双马战车编队——青铜时代战场的主宰（赫梯/商/埃及战车）"**。
- 所以"战车"不是无指定；它已经是**双马**。若要做四马：
  - 新增单位 211 `四马战车兵`（更高攻击/防御/成本/补给），`UnitDef.requiredInnovations = [1013, 新四马战车革新]`；
  - 或扩展 `UnitDef` 增加 `mountCount/vehicleType` 字段（影响兵种系统，需单独设计/平衡）。
- 不能写"战车制造"；要么沿用 1013 `双马战车`，要么新增 `四马战车` 单位/条目。

### 8.3 酿造：现有 913 是"米谷发酵"（谷物酒），但目前没有酒类物产/配方/效果
