# 技术史笔记：工艺、型制、能力与技术系统

> 目的：为"技术器物类革新"提供历史学/技术史依据，避免把技术史简化成一条线性科技树。
> 方法：以技术史通行的"发明—创新—扩散""宏观发明/微观改进""技术系统"框架，对照火药/火器/攻城/弩/船/车等具体序列。
> 参考：Wikipedia 技术史条目（History of technology / gunpowder / firearms / matchlock / flintlock / crossbow / siege engine / trebuchet / caravel / carrack / galleon / wheel / chariot / printing）；Mokyr《The Lever of Riches》《The Gifts of Athena》；Rogers《Diffusion of Innovations》；Hughes 技术系统研究；OECD Oslo Manual（产品/工艺/组织/市场创新）。

---

## 1. 技术史的几个基本区分

### 1.1 发明 ≠ 创新 ≠ 扩散

- **发明（invention）**：第一次做出某个原理/构型。
- **创新（innovation）**：把它变成可稳定使用、可复制、可组织的做法/产品/系统。
- **扩散（diffusion）**：被其他群体/地区采用、改造、再发明。

技术史上很多"发明"长期停留在玩具/仪式/单一用途；只有完成**工艺稳定、材料配套、组织采用**才算创新。  
→ 游戏里不能只按"谁先发明"给节点；要有 `discoveryGroups`/采用条件/区域变体。

### 1.2 宏观发明 vs 微观改进

Mokyr 区分：
- **宏观发明（macroinvention）**：新原理/新构型（火器、印刷机、蒸汽机）；
- **微观改进（microinvention）**：在同一构型内提高效率/可靠性/成本（更好的枪机、更好的炮管、更好的装填）。

→ 不是所有改进都要立新条目；同型制内的改进应做**效果/质量/成本修正**，否则科技树会碎成一堆"更好的X"。

### 1.3 产品/工艺/组织/市场

Oslo Manual 的四类：
- product（新产品/型制）
- process（新工艺/工序）
- organizational（新组织/制度）
- marketing（新市场/营销）

历史技术史还要加：
- **Idea/Knowledge**（原理/知识）
- **Practice**（做法/惯例/训练）

→ 我们的 `InnovationKind` 用 `Technique / Pattern / Institution / Practice / Idea / Knowledge` 是合理的；`Pattern` 专门表示"具体型制"，不是泛器物名。

### 1.4 技术系统（technological system）

Hughes 的技术系统观：一个可用技术不是单件器物，而是**互相依赖的组件 + 组织 + 技能 + 基础设施**。

例：火绳枪不是"一根枪"：
```text
黑火药（配方/颗粒/储存）
+ 金属枪管（铸造/钻孔/耐压）
+ 点火机构（火绳/枪机/扳机）
+ 装填训练（战术/编制）
+ 后勤（火药/铅弹/备件）
= 火绳枪系统
```
→ 单条"火器"革新无法表达；应按**工艺/型制/能力**拆成多个节点，并用 `affinityTags`/`systemTags` 表示同一系统。

### 1.6 中性名称原则

技术史比较要求**中性技术描述名**，不依赖文献、语言、文化专名或文学绰号，而按：
- 动力来源（人力/畜力/水力/风力/配重/扭力/张力/火药）；
- 结构（梁/拱/架/轮/顶棚/悬挂/铰接）；
- 运动方式（抛射/撞击/攀越/挖掘/移动）；
- 作用对象（门/墙/壕/城/人/船）。

例：
- `配重式投石机` 可对应 trebuchet/manjaniq/中国配重抛石机；
- `覆顶撞门车` 可对应 testudo arietaria/中世纪冲车/临冲；
- `移动攻城塔` 可对应欧洲 siege tower/中国吕公车。

史料专名只放来源/别名，不进入规范名。详见 [TECH_ARTIFACT_INNOVATION_MODEL.md](TECH_ARTIFACT_INNOVATION_MODEL.md) §1.1。

### 1.5 非线性和多中心

技术史不是欧洲单线：
- 火药/印刷/纸/指南针有东亚起源与扩散；
- 冶金、造船、灌溉、数学有多中心；
- 同一功能可由不同型制实现（投石机 vs 火炮；弩 vs 弓；帆 vs 桨）。

→ 避免"某时代必点某科技"的单一路径；用区域变体/`prerequisitesAny`。

## 2. 关键序列（按工艺—型制—能力）

### 2.1 火药

| 阶段 | 工艺 | 型制/用途 | 能力 |
|---|---|---|---|
| 火药配方 | 硝石/硫磺/木炭配比 | 火药（物产） | 燃烧/爆炸/推进 |
| 提纯 | 硝石提纯 | 精制火药 | 稳定燃烧、威力 |
| 颗粒化 | 湿法造粒 | 粒状黑火药 | 运输稳定、燃烧一致 |
| 火器化 | 装药/点火 | 火门枪/火绳枪/火炮 | 射击/攻城 |
| 无烟化 | 硝化纤维 | 无烟火药 | 高初速、低烟（近代） |

→ 游戏第一批：`黑火药配制`（207 已迁移）；`火药`是物产；`颗粒化`/`硝石提纯` 按需。

### 2.2 火器

| 型制 | 击发/装填 | 能力差异 | 历史节点 |
|---|---|---|---|
| 火门枪/手铳 | 手动点火 | 短程、慢、不可靠 | 13–14 世纪 |
| 火绳枪 | 火绳枪机 | 可瞄准、齐射 | 15 世纪 |
| 燧发枪 | 燧石击发 | 更可靠、射速提高 | 17 世纪 |
| 线膛枪 | 膛线+米涅弹 | 射程/精度大幅提高 | 19 世纪 |
| 后装枪 | 后膛闭锁 | 装填速度质变 | 19 世纪 |
| 火炮 | 炮管/炮架 | 攻城/野战/曲射 | 14 世纪起 |
| 火箭 | 火药推进 | 面杀伤/纵火 | 东亚/南亚 |

→ `307 火器` 已改为 `火绳枪`；下一步按能力差异加 `手铳`、`燧发枪`、`射石炮/臼炮/长管炮/野炮`，不是一次全加；`攻城炮`只作功能类别，不作条目名。

### 2.4 弩

| 型制 | 张弦机构 | 能力 | 备注 |
|---|---|---|---|
| 手弩 | 臂张 | 便携、射速 | 小型 |
| 蹶张弩 | 脚踏/腰开 | 张力大、穿甲 | 需要弩机 |
| 腰开弩 | 腰/坐姿 | 更强张力 | 区域变体 |
| 床弩/弩炮 | 架座/绞盘 | 大威力、攻城/海战 | 需要架座 |
| 连弩 | 弹匣/连发 | 射速 | 复杂机构 |

### 2.5 船

船的技术史要拆三层：

| 层 | 维度 | 例子 |
|---|---|---|
| 船体形态 | 浮力结构 | 筏（木/竹/浮囊）、独木舟、木板船（搭接/平接）、双体舟/舫、复合结构船 |
| 动力系统 | 推进方式 | 撑篙、划桨、橹、拉纤、横帆、纵帆、混合帆、桨帆并用、轮桨、明轮蒸汽、螺旋桨蒸汽/内燃机 |
| 用途 | 功能 | 内河货船、远洋货船、客船/渡船、渔船、漕运船、工程船、拖船、战船 |

规范名只取主要差异轴，三层信息放标签/数据，不拼成长复合名：

- `独木舟`（hull:dugout）
- `木板船`（hull:plank）
- `横帆船` / `纵帆船`（propulsion:sail）
- `桨帆船`（propulsion:oar-sail）
- `远洋货船` / `内河货船`（function:cargo）
- `明轮蒸汽船`（propulsion:paddle-wheel-steam）

注意：

- `长船` 不是战船专名，是**窄长船体 + 桨帆并用**的标签组合；
- `风帆战舰` 不是船类本名，是**风力帆船 + 舷侧火炮模块**的标签组合；
- `三列桨/五列桨` 是桨手层数/布置的修饰，不是独立船类；
- 史料船名（卡拉维尔/克拉克/盖伦）只作来源/别名，规范名用短中性名。

→ 现有 400~406 应逐步改为三轴规范名；优先保留**船体/动力/用途的能力差异**，不合成“造船”一条。

## 3. 对模型的修正

### 3.1 增加 `Pattern`（型制）

已加 `InnovationKind.Pattern`：
- 只用于**具体构型**，且该构型有独立能力差异；
- 不用于"火器/攻城器械/弩"等泛称；
- 型制的具体实例仍应落到 `EquipmentDef`/`UnitDef`/`BuildingDef`。

### 3.2 用 `affinityTags` 表示技术系统

现有 `affinityTags` 已有 `Chariot`、`Press`、`Manor`、`Navy`，可扩展为技术系统标签：
- `GunpowderWeapons`：黑火药配制、手铳、火绳枪、火炮；
- `SiegeEngineering`：牵引式/配重式/扭力投石机、覆顶撞门车、移动攻城塔、车载张力弩；
- `Navigation`：罗盘、星盘、海图、船型；
- `Papermaking`：纤维打浆、抄纸成型。

不需要新增 `System` kind；用标签聚合即可。

### 3.3 把"改进"留在型制内

同型制的改进（更好的枪机、更耐压的炮管、更快的装填）先用：
- 质量/成本/可靠性的 `capabilityModifiers`；
- 或 `InnovationVariant`；
不要为每个小改进立新条目。

### 3.4 组合前提

型制/系统需要多个互补前提：
- 火绳枪：黑火药 + 金属管 + 枪机 + 装填训练；
- 火炮：黑火药 + 铸炮 + 炮架 + 弹道知识；
- 移动攻城塔：木工 + 轮轴 + 结构工程 + 人力组织。
→ 用 `prerequisites` 全部必要 + `prerequisiteRationale`；不要用单个"火药"或"铁"概括。

### 3.5 区域变体与扩散

- 同一功能允许多条路径（投石机/火炮；弩/弓；帆/桨）；
- 区域型制用 `InnovationVariant`（如 `keju`、罗马公民权）；
- 扩散条件用 `discoveryGroups`/`requiredCapabilities`，不要默认全球同步。
