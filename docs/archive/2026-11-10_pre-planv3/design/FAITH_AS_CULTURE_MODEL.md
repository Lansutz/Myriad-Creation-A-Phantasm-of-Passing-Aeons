# 信仰系统：只借「分裂」与「挂靠」，主运行单位是传统（修正版）

> 2026-11-09 修正。之前我把信仰当成"文化式运行单位（faith 为核心）"，错了。
> 用户口径：只借鉴族群/文化的**分裂机制**和**挂靠机制**，不是整体照搬；二者挂靠不等同；**主运行单位是传统**；宗教层固定、不会消失，中间有一层可选。
> 性质：设计草案，不改代码。

## 0. 三条硬口径

1. **主运行单位 = 传统（Tradition）**，不是 faith、不是 community。
2. **宗教层固定、不可消失**；中间层**可选**（可有可无）。
3. 只借两件事：**分裂机制**、**挂靠机制**；其余（地区构成、相似度、阶段、文化谱系等）不整体照搬。

## 1. 层级

```text
宗教 Religion        ← 固定层，不消失，不因分裂而消失
  └─ 中间层（可选）   ← 名称待定（信仰/教派/宗门）；可以没有
       └─ 传统 Tradition   ← 主运行单位；机制、分裂、挂靠都在这里发生
```

| 层 | 固定？ | 可消失？ | 说明 |
|---|---|---|---|
| 宗教 | **固定** | **否** | 顶层身份容器，分裂不改变宗教层 |
| 中间层 | 可选 | 可有可无 | 有则挂靠，没有也成立 |
| 传统 | 主单位 | 可分裂/演化/消失 | 传统集合的分化就是"分裂"的实际内容 |

## 2. 挂靠机制（只借这一半，且与族群不等同）

| 挂靠 | 族群/文化 | 信仰 |
|---|---|---|
| 主体→上层 | 族群挂靠**可有可无** | **宗教身份不可无**（宗教层是必填） |
| 可选中间层 | — | 中间层可选：有就挂，没有也成立 |
| 传统 | — | 传统必须挂在某个宗教下；中间层可选 |
| 个人 | 族群认同可多层/可弱 | **宗教归属必填**；中间层/传统可弱/可选 |

结论：

- 挂靠的**基数不同**：族群挂靠 optional；宗教挂靠 mandatory。
- 不能把族群的"嵌套+渠道+阀门+显著度"整套搬过来——那套假设了"认同可弱可无"，宗教身份不适用。

## 3. 分裂机制（只借这一半，但规则不同）

| 对比 | 文化 | 信仰 |
|---|---|---|
| 分裂结果 | 产生新 CultureData（parentCultureId/childCultureIds） | **宗教层不变**；分裂发生在中间层/传统层 |
| 分裂单位 | 文化 | **传统集合**（传统增删/替换/分化） |
| 上层 | 文化可再分 | 宗教固定，不因分裂产生新宗教 |
| 记录 | 文化谱系 | 传统谱系 + 挂靠变更记录（中间层/传统） |

- 分裂的**实际载体是传统**：传统集合差异扩大 → 中间层/传统分化；
- 宗教层只做固定容器：分裂不会让宗教消失，只让下面的传统/中间层变多或变少。

## 4. 数据层（草案）

```text
ReligionDef（内容，固定）      // 顶层，不可空
MiddleLayerDef（内容，可选）   // 名称待定：信仰/教派/宗门
TraditionDef（内容/运行时，主单位）
  ├─ traditionId, religionId（必填）, middleLayerId（可选）
  ├─ doctrine/rite/org 组件
  ├─ parentTraditionId / childTraditionIds（分裂谱系）
  └─ practices/scope

PopulationTraditionComposition   // 地区/人口的传统构成（shares）
CharacterData
  ├─ religionId（必填）
  ├─ middleLayerId（可选）
  └─ traditionIds[]（可选/弱）
```

- 地区构成以**传统**为统计单位，不是"信仰 adherence 单值"。
- 传统文化化只借"传统是可组合条目"这一点；**不**引入文化相似度、文化阶段、文化谱系那一整套。

## 5. 与头衔指代的衔接

| 头衔类型 | 指代 |
|---|---|
| 教职（主教座、教区） | 传统/中间层 + 官职机构 |
| 宗教上层称号 | 宗教（固定层） |
| 神庙/祭司 | 传统 + 神祇（传统内部）+ 聚落 |
| 主保/圣人 | 传统 + veneratedDead |
