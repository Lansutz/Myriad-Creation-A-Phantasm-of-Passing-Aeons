# Architecture 2.0 — 法律域/组 · 头衔 · 继承三轨 · 键名过滤 · 法理区域 模型设计稿

> 状态：研究设计稿。先确定数据语义与边界，再迁移代码。代码层尚未改动、未编译验证。
> 分支：architecture-2-0-refactor
> 参考边界：CK3 与 Things That Happen on the Map（下称 TTHTOM）只作机制概念研究对象，不复制其文件结构、脚本语法或实现限制；凡我方独有需求（语言字段、自生成法理、键名命名空间）在对应小节单独标注。

## 1. 目标与范围

把旧代码里残留的旧五分类法律域（`Internal/Military/Religion/Economic/Social`）与另一套旧条文分类（`LawCategory` 七值）替换为三层结构，**归集顺序从下到上：先定法律组，再归法律族，最后归法律域**：法律组是最低层、一道题一组、题内选项互斥或累积，部分选项带前置依赖链式激活；法律族是同主题几个组的内部归类；法律域作为最粗粒度接口供秘密、罪名、派系等其他系统引用。同时为几条制度线定下数据模型：

- 可无限扩展层级、上级可挂靠上级的头衔实体与组件模块（原官职并入头衔管理器）；
- 国家继承轨、家族继承轨、地方继承轨拆分，重复枚举去重；
- 罪行管理器：多条行为归集为罪名定义，对象 / 场景字段限定，法律条目反向引用；司法只留执行层；
- 派系按利益动态聚合，诉求引用法律域，区分借鉴与不照搬 CK3 的部分；
- 键名命名空间 + 条件过滤 + 可选数量上限的命名系统；资格为硬约束，权重只在通过硬约束的候选内排序；
- 自生成、可长期漂移、层级有限的法理区域（de jure region）。

本稿不决定数值平衡、全部头衔实例清单、完整法律条文目录与 UI 布局。现有九维政体组织骨架（最高/中央/地方三层 × 交接/分配 + 央地结构）保留，归入建制域最高权力、中央权力、地方权力、结构四族，见 4.5。

## 2. 参考模型取证

### 2.1 TTHTOM（pck 解包 + 内置文明 JSON + strings + gdc 类名映射）

**政权与中央机构（可配置预设，非硬编码政体）**

- 国家层只有两套预设：`term.national_government.monarchy`、`senate_republic`；地方层两套：`governorate`（总督制）、`lordship`（领主制）；另有 `office_rule`（官职制）。预设内部完整配置清单在编译字节码内不可读，我方以其可见字段结构为准。
- 中央机构可选：`none`、`censorate`（御史台）、`chancellery`（宰相府）、`senate`（元老院）。

**官职三层字段差异（内置三份文明去重）**

- 国家元首层（head）独有：`inheritable`、`enabled`、`personnel_weight`、`names`、`rank`、`salary`、`superior_office`、`term_years`。
- 中央层（central）独有：`can_promote`、`dismissal_resistance`、`name_color`、`residence`、`superior_office`、`term_years`、`rank`、`salary`、`personnel_weight`、`names`。
- 地方层（local）独有：`base_loyalty`、`can_promote`、`dismissal_resistance`、`enabled`、`inheritable`、`name_color`、`seats`、`rank`、`salary`、`superior_office`、`term_years`。
- 三层公共字段：`annual_prestige`、`appointment_order`、`candidate_gender`、`candidate_royal`、`candidate_scope`、`candidate_institution`、`design_id`、`family_power`、`id`、`modules`、`names`、`personnel_weight`、`rank`、`salary`、`superior_office`、`term_years`。
- `modules` 是模块名→布尔字典（不是数组），跨文明去重得 11 种：`personnel_authority`（人事权）、`general`（统帅）、`central_office`（中央机构）、`culture_spread`（文化传播）、`family_grant`（家族授予/采邑）、`local_construction`（地方营建）、`local_ruler`（地方统治）、`unrest_overthrow`（可被民变推翻）、`central_construction`（中央营建）、`head_of_state`（国家元首）、`monarchy`（君主制）。
- `appointment_order` 是可多选数组：`election`、`personnel_appointment`、`inheritance`、`royal_grant`、`superior_appointment`。
- 资格字段：`candidate_gender`（三份文明全填 `any`，字段预留未用）、`candidate_royal`（`any` / `non_royal`）、`candidate_scope`（`country` / `culture`）、`candidate_institution`（多为空，`senate` 一例）。
- `rank` 编号可继续向下扩展；`superior_office` 上级挂靠三层都预留，实例内多留空。
- 议事会实例：`kind=assembly`、`office_ids` 成员官职列表、`max_seats_per_family`、多语 `names` / `descriptions`。

**预设与席位权重（外置两份文明 JSON 可见，内置三份缺这层）**

外置两份 JSON 分别是我方预设形态的对照：`不涂.civilization.json` 是空字段默认模板（新建文明时的字段骨架），`逐鹿文明.civilization.json` 是填充完整的战国范例（官职、模块、席位、命名池、预设都已落值）；我方默认预设参照空模板的字段完整度，模组自定义参照填充范例的覆盖方式。

- `polity_profile`：`central_presets`、`local_presets`、`office_seats`（官职 id→席位数，0 = 不设该职）、`default_central_preset`、`default_local_preset`、国名模板。
- 每个 preset 内含 `office_seats`（覆盖默认席位）、`office_variants`（官职 id→变体 id，对应 CK3 同一官职按语境切换称谓）、`generation_weight`（生成抽取权重，0 不参与，全 0 用默认）。
- `summary` 是派生汇总而非手写：意识形态四维汇总；君主制倾向 = 元首基准 50% + 中央官职席位加权 50%；地方 alignment 由 `ruler_share`、`inheritance_score`、`term_score` 合成；每个官职记 `ideology`、`seats`、`share`（席位权重占比）、`weight`（单席权重）、`total_weight = weight × seats`。
- 意识形态四维：`elitism`（平民—贵族）、`expansion`（发展—扩张）、`monarchy`（共和—君主）、`xenophobia`（亲外—排外）；人物基准只参与出生初值，不持续约束、不追溯既有人物。

**继承三轨并存（不是一套继承法）**

- 总轨 `Succession`；国家元首轨 `NationalMonarchSuccessionEvent`、`NationalElectionEvent`、`NationalByElectionEvent`；城市领主轨 `CityLordSuccessionEvent`；家族家主轨 `FamilyHeadSuccessionEvent`。
- 默认继承四轴存 0~1 连续倾向权重（`scope` / `line` / `gender` / `birth_order`），`birth_order` 离散为 `eldest` / `youngest`。这与我方离散档位继承法不同，仅作权重合成思路参考。

**税法两层（不追溯既有城市）**

- 国家税法：`heavy` / `light` / `none`，按份额；城市本地税法可单独设本城上缴重/轻/免。国家税法只作用于新成立与新征服城市的初始税率。
- 城市忠诚因子：本地统治者基准、同文化、空缺、领主制基准、免税优待、重税惩罚；税收容量与不安按总督/地方官/领主治理能力计算。

**法理（de jure，静态依附型）**

- 省份作为 de jure 簇归属某个城市；事件 `DeJureRequestEvent`（索取/报价/拒绝/归还）、`DeJureSaleEvent`（成交/拒绝/无力支付）。
- 限制条件：任一方战争中、五年交涉冷却、一方已覆灭、实体无效、簇已不存在、簇内仍有被占领或围攻土地、已有待答复报价、同一附庸集团内但并非直接宗主附庸；总开关 `de_jure_integrity`。
- TTHTOM 法理是静态省份簇挂城市，靠交涉/买卖转移；我方要做的是其之上的**自生成层级区域**（见 2.3 与第 8 节）。

**命名系统（词库模型，我方键名管理的反面参照）**

- `naming_profile` 按用途池 id 分组：country / family / surname / given male / given female / place prefix-suffix / army / national army。
- 规则四类：`literal`（整词直取）、`affix`（前缀+后缀+分隔符，可分语种）、`generation`（字辈池按世代循环）、`template`（槽位拼装，多语模板）；配 `weight`、`enabled`、`generation_rule_priority`。
- 池只按文明隔离（池 id 带文明前缀），同 ID 跨文明不共享；**没有按政权/族群/头衔/官职类型再分命名空间，没有文化/族群/信仰/语言/地理/地形条件过滤，没有数量上限**；locale 只是渲染层，不是资格过滤维度。CK3 同样没有语言字段。这两处是我方要补的差距。

**军事与地图**

- 国家军 / 城市军双轨；编制支数上下限 + 人口增量；维护费分付费兵种与农兵（裁撤时农兵不动、付费兵按维护费比例裁减）；士气、补给线、围攻进度、溃退归建、寻路拟真/性能模式。兵种清单在不可读字节码内，strings 仅有浮动提示，不作为我方设计依据。
- 地图：`province{id,name,center,country_code,country_name,source_level,source_key,group_field}`；`cells{cell_center[],cell_province[]}`；manifest 记宽度高度、海域标高、高度图、省份/地块计数、目标像素面积、分裂因子、各统计分位、源层级。

### 2.2 CK3（实读 common 源码）

**法律组 `law_group`**

- 字段：`required_government_flag`（前置政体开关，不满足整组隐藏）、`default` 默认法律、`cumulative`（档位是否叠加）、`flag` 能力标签、`can_have_group`（组级挂载条件，如教会俸禄组要求存在选举主教头衔）。
- 帝国官僚、天国官僚、封建权威、教会权威、游牧权威、曼荼罗、 meritocratic 等组各自挂 `required_government_flag`；`crowned_laws` 为 `cumulative = no`。

**单条法律 `realm_law`**

- `law_group_type` 归属组、`index` 档位序号、`modifier` 效果（意见/数值）、`flag` 能力开关（头衔收回、附庸撤回、可设 tributary、可改分割继承等）、`can_keep`（保留条件：政体匹配、与领主法律同步 trigger_if）、`can_pass`（通过条件：前置法律、冷却变量、革新豁免、`custom_description`）、`on_pass`（触发效果）；配威望/虔诚成本与冷却年数常量。
- 行政法组实例：`province_war_law`（战争状态行省法）、`province_border_law`（边境法，非叠加）、天国文武/退休法、`border_wars_laws`、摄政/秘书处法、`candidate_score_laws`（选贤/世袭评分法）、三组预算法（人事/大臣/军事，`required government_has_treasury`、`is_treasury_budget_group`）。教会法组：`budget_allocation_cardinal`（`required government_is_ecclesiastical`）、`church_benefices_law`（`can_have_group = exists clerical_elector_title`）。

**继承分组独立**

- `succession_order_laws`（含 `can_change_law_group` 自定义条件 tooltip）、`succession_gender_laws`（独立成组，默认男子偏好）、`succession_faith`、`succession_rel_head`；头衔继承法 `title_succession_laws` 组 `can_have_group = { always = no }`，默认不挂载，独立于王国继承。
- 头衔继承单条：`can_have`（政体 flag + 头衔 tier + 文化参数排除）、`can_pass`（改头衔法 trigger）、`can_title_have`（具体头衔）、`succession{order_of_succession, election_type}`、`flag`、意见、`revoke_cost`、`pass_cost`、`modifier`。

**官职 `council_positions` / `ministry_positions`**

- `skill` 对应属性、`name`、`valid_position`（职位在当前政体是否开放）、`tooltip.first_valid`、`auto_fill`、多条 `modifier`（可带 `scale`：按宗主 tier / 月收入 / 行政值缩放）、`council_owner_modifier`（任职者加成）、`valid_character`（候选人资格 trigger，部长存在时走独立 trigger）、`on_get_position` / `on_fired_from_position` 效果、`portrait_animation`。
- 称谓 `name.first_valid` 多个 `triggered_desc`，按头衔 tier、政体 flag、是否独立统治者、是否总督切换称谓——我方文化称号变体链直接参照这一层。

**头衔键名**

- 前缀语义：`h_` 霸权/帝国位、`k_` 王国、`d_` 公国、`c_` 郡国、`b_` 堡；`can_create` 走 scripted trigger 条件过滤；另有 `capital`、`definite_form`、`can_be_named_after_dynasty`、`no_automatic_claims`、`always_follows_primary_heir`、`destroy_if_invalid_heir`、`can_use_nomadic_naming`、`can_destroy`、`ai_primary_priority`、`color`。

### 2.3 我方独有、参考模型没有的部分

- 语言资格过滤：候选/称谓/命名池按语言匹配，CK3 与 TTHTOM 都没有。
- 自生成法理区域：随文化、族群、地理、世界观、政治行政规划长期漂移，与行政层级挂钩；不是预定义固定省份，也不是 TTHTOM 静态省份簇。
- 键名命名空间：政治实体、族群、头衔、家族、人物、聚落、法理区域、军队、建筑、机构各自隔离；创建或自主生成时自动生成键名并存档持久化。

## 4. 法律域 / 法律族 / 法律组（从下到上：先定组，再归族，最后归域）

### 4.0 三层定义与归集顺序

- 归集顺序是**从下到上**：先盘点代码里现存的每一道选择题定组，再把回答同一主题、相互前置或互补的几个组归族，最后把族按对外引用需要归域；不先设域、族再往下塞题。
- **法律组 `LawGroup`**：最低层，**一道题就是一个组**，一组内若干档位互斥或累积；选中父选项后才出现的链式子选项是**题内子题**，不独立成组。每组带默认值、是否累积、前置条件；前置未满足时整组隐藏 / 置灰，题内子题按父选项激活。
- **法律族 `LawFamily`**：同一主题的几个组打包成一族，只在法律系统内部归类，不对外暴露；不为单个组另造空族（一组一族仅用于该族确有独立主题时）。
- **法律域 `LawDomain`**：最粗粒度对外接口。秘密系统、罪名定义、派系诉求、资格约束等不挂具体题、组或族，只引用域；域由族向上归拢。建制域由原"政体组织 / 政治组织"改名而来，不是另起一套。
- 挂接规则：`State/Law.cs` 条文条目挂组；法律族内部归集；秘密、罪名、派系、资格等系统引用域。
- **内部命名与玩家可见名分离**：域、族、组、题、子题都是代码内部归类与键名，**不进入游戏内 UI 文本，也不进游戏内百科**；界面上只显示该政权实际可见的中性拟真名称（如"建制"），不出现"域""族""组"这类系统词。本稿 4.2 枚举注释里的"最高权力族""境内治理域"等中文只是开发参考称谓，不是 locale 文案；法律各族、各组、各题、各档位的可见名称另行登记 locale 条目。游戏内百科只收可见术语，锚点等内部机制同样不进百科。
- 命名中性：不用政权不会自称的贬义词（如"迫害"），底线之上允许风味化、贴合拟真语境。

### 4.1 代码取证：现存题清单（分组的唯一依据）

分组只以代码里已经存在的选择题为依据；预留占位组在 4.6–4.9 单独登记，不与现存混排。

**A. 最高权力主题（现存，归入最高权力族）**

- 归属题 `SupremeSovereignty`：君主制 / 共和制
- 交接题 `SupremeSuccession`：世袭 / 直接选举 / 代议推举 / 僭夺 / 轮座 / 神命
  - 题内子题：世袭 → 继承法四轴（范围 / 支系 / 性别 / 长幼）；直接选举 → 选举范围 + 性别资格；代议推举 → 推举主体 + 性别资格
- 范围题 `SupremeScope`：全能 / 法理受限 / 惯例约束 / 共议制约 / 神意约束
- 头衔分配题 `TitleDistribution`：独享 / 家族共享 / 有最高头衔 / 无最高头衔（选项按君主 / 共和过滤）
- 领地分配题 `DomainDistribution`：独享 / 均分 / 采邑

**B. 中央权力主题（现存，归入中央权力族）**

- 有无题 `CentralExistence`：无常设 / 有常设
- 交接题 `CentralSuccession`：任命 / 选举 / 考试 / 世袭
- 机构题 `CentralInstitution`：无常设 / 王庭 / 议会 / 长老议事会 / 官僚中枢 / 宗教会议 / 军事委员会
  - 题内子题：议会 → 议会构成（一院 / 两院 / 等级会议）；长老议事会 → 长老构成（氏族 / 贵族 / 功勋）；官僚中枢 → 官僚体系（三省六部 / 三公九卿 / 部院制）
  - 前置：机构题子题仅在中央有常设时出现

**C. 地方权力主题（现存，归入地方权力族）**

- 交接题 `LocalSuccession`：任命 / 选举 / 考试 / 世袭 / 城市特许
  - 题内子题：任命 → 任命主体（中央派任 / 教区委任 / 军事任免）；世袭 → 领有身份（封臣 / 宗室采邑 / 军功领邑）；选举 → 选举范围（本地公民 / 部落 / 自治市议会）；考试 → 考试体系（科举 / 文官考试 / 荐举 / 九品中正）；城市特许 → 特许类型（自由市 / 帝国自由市 / 特许市镇，可选）
- 职能题 `LocalScope`：全权自治 / 征税司法 / 仅军事驻防 / 完全直辖

**D. 结构主题（现存，归入结构族）**

- 结构题 `SpatialStructure`：单一制 / 联邦制 / 邦联制

**横切资格（依附各交接题，不是独立选择题）**

- 最高 / 中央 / 地方三层 `EligibilityRules`：性别五档（仅男 / 男优 / 平等 / 女优 / 仅女）+ 资格范围六类（本族 / 公民 / 贵族 / 教阶 / 自由民 / 全体）；先按资格硬过滤，再按交接方式排序。

**执行层附属（不是法律选择题，不进组）**

- `JudicialSystem`：司法效率、腐败、执法强度、严厉度、六种刑罚开关、审判流程；`LawSource` 法源六值现状挂在司法系统上，4.9 提升为法源组。
- 罪名 15 种、刑罚 9 种属罪行管理器与执行层，见 4.10。
- `LawCategory` 旧七值是被否决的平行分类，废弃。

**E. 预留占位（代码未实现，登记组位）**：兵役制、军队组织、国教地位、圣俗优先、异教政策、国教头衔、户籍、土地所有制、婚姻身份、阶层公民权、货币度量衡、贸易管制、国家税法、地方税法、关隘通行、边市。

### 4.3 族归集（几个组按主题打包，从组选项语义判断）

- **最高权力族 `SupremePower`**：归属、交接、范围、头衔分配、领地分配五组。都回答政权顶端权力归谁、怎么交接、受什么约束、顶端头衔与领地怎么分；选项之间存在明确前置与互补（归属过滤交接与头衔分配可用选项），同题同族。
- **中央权力族 `CentralPower`**：有无、交接、机构三组。回答中央有没有常设机构、成员怎么产生、常设机构是什么形态。
- **地方权力族 `LocalPower`**：交接、职能两组。回答地方职位怎么产生、地方保留多少职能。
- **结构族 `RealmStructure`**：央地结构一组。回答法定主权在中央与地方之间怎么划分。
- **军政族 `Military`**：兵役组、军队组织组。回答武装力量怎么征召、怎么编成；与建制域内各权力族里的职位归属不同，这里不涉及职位归属，只涉及武力建制。
- **信仰治理族 `FaithGovernance`**：国教地位、圣俗优先、异教政策、国教头衔四组。回答政权如何对待境内宗教；四组链式前置：先立国教，才开放后三组。
- **身份族 `Household`**：户籍、土地所有制、婚姻身份、阶层公民权、姓名登记五组。回答政权如何把人编入身份秩序；人身秩序类罪名对外挂本族。姓名登记组规制固定身份标识的范围、继承线与登记用途，是法律产物，详见 5A.3A。
- **财货族 `Economy`**：货币度量衡、贸易管制、国家税法、地方税法四组。回答政权如何管理财货流通与征敛；财产、欺诈、税务类罪名对外挂本族。
- **边域族 `Frontier`**：关隘通行、边市互市两组。回答政权如何管控边境出入口岸；与财货族的区别在管制空间与通道，不在市场交换本身。
- **法源族 `LegalSource`**：法源组一组。回答政权的法律从哪里来；宗教法源在此引用亵渎、异端罪名，不挂信仰治理族。

### 4.4 域归集（族向上归拢，供其他系统引用）

| 法律域 `LawDomain` | 收拢的族 | 对外职责 |
|---|---|---|
| `Institutional` 建制域 | 最高权力族、中央权力族、地方权力族、结构族 | 政权组织、权力交接、央地结构、公职资格 |
| `Military` 军事域 | 军政族 | 兵役、军队组织、军职纪律 |
| `Faith` 信仰域 | 信仰治理族 | 政权对境内宗教的治理态度，不含法源 |
| `Governance` 境内治理域 | 身份族、财货族、边域族 | 身份秩序、财货征敛、边境通道 |
| `LegalTradition` 法源域 | 法源族 | 法源体系；宗教法源在此引用信仰类罪名 |

- 罪名引用域归属：军职罪名挂军事域军政族；人身罪名挂境内治理域身份族；财产、欺诈、税务罪名挂境内治理域财货族；走私为边域族与财货族双向引用、主引用域挂境内治理域；亵渎、异端挂法源域法源族（宗教法源），不挂信仰治理族。
- 不设独立司法刑律组：罪名由罪行管理器归集多条行为，法律条目反向引用；审判与刑罚执行留在 `JudicialSystem`。

### 4.6 军事域 · 军政族（预留，档位待拍板）

- 兵役组：常备军 / 征兵制 / 封建采邑兵 / 雇佣军 / 部落征召；
- 军队组织组：国家军 / 城市军 / 领主军（参照 TTHTOM 双轨，预留第三轨）；
- 军职犯罪（擅离职守等）对外引用军事域，罪名定义见 4.10。

### 4.7 信仰域 · 信仰治理族（预留，链式前置）

本族只表达政权对境内宗教的态度，不直接引用罪名；亵渎、异端由法源域宗教法源引用（见 4.9、4.10）。

1. 国教地位组：无国教 / 有国教。
2. 圣俗优先组（前置：有国教）：教法优先于一般法 / 一般法优先于教法 / 圣俗并行。这是“同奉国教也有差别”的核心字段。
3. 异教政策组（前置：有国教）：宽容并立 / 限制管控 / 禁绝公开信仰。措辞用中性管理视角，不用“迫害”类贬义词。
4. 国教头衔组（前置：有国教）：是否设国教头衔，与第 5 节模块 `religious_office` 挂钩。

### 4.8 境内治理域 · 身份 / 财货 / 边域三族（预留，档位待拍板）

- 身份族：户籍组、土地所有制组、婚姻身份组、阶层公民权组、姓名登记组；人身秩序；人身类罪名对外挂本族。姓名登记组档位：固定标识范围（无固定标识 / 仅贵族世袭氏 / 全民固定姓）、继承线（父系 / 母系 / 双系 / 自选，无固定标识时不生效）、登记用途开关（户籍 / 税册 / 军籍）、改姓与赐姓许可（禁止 / 特许 / 自由）、婚名归属（保留本姓 / 从夫 / 从妻 / 双姓）；开放全民固定姓需先持有户籍、税册或军籍类革新，详见 5A.3A。
- 财货族：货币度量衡组、贸易管制组；税法两层——国家税法组与聚落本地税法组（参照 TTHTOM：国家法只作用于新成立 / 新征服聚落的初始税率，不追溯既有聚落）；财产、欺诈、税务类罪名对外挂本族。
- 边域族：关隘通行组、边市互市组；走私为边域族与财货族双向引用，主引用域挂境内治理域，罚金计算口径走财货族；边市互市与贸易管制的区别在于通道管制而非市场规则。

### 4.9 法源域 · 法源族（现存 `LawSource` 提升）

法源组：习惯法 / 成文法 / 宗教法 / 普通法 / 大陆法 / 混合法。宗教法源负责引用亵渎、异端等信仰类罪名（见 4.10），与 4.7 信仰治理族分工：宗教法是法源本身，信仰治理是政权对境内宗教的态度。刑罚偏好、刑罚开关、司法效率与腐败留在 `JudicialSystem` 执行层，不进本组。

### 4.10 罪行管理器与罪名定义（借鉴 CK3 罪行定义，不设独立刑律组）

**模型：行为（原子标签）归集为罪名定义，罪名定义可挂多条行为，再由法律反向引用**

1. **行为标签 `behaviors`（原子词表，可复用）**：杀人、伤害、盗窃、侵占、欺诈、背叛、通敌、密谋、亵渎、背离教义、擅离职守、违禁转运……行为是最小可匹配单元，本身不是罪名。
2. **罪名定义 `CrimeDefinition`（名义实体）**：一个罪名归集**一条或多条**行为——同一个罪名可以由好几条不同行为落入（叛国可以包含通敌、密谋、谋逆、出卖政权利益；盗窃可以包含窃取、侵占、夜窃）。罪名定义登记：
   - `behaviors`：可落入本罪的行为标签列表，非空；
   - `target_class`：可选，本罪行为指向的身份或阶层（元首、官员、贵族、平民、商人、家族成员、同信仰者、财产所有人……）；留空表示不限对象；
   - `context`：可选场景限定（战争中 / 和平期 / 公职中 / 夜盗……），不是每条罪名都需要；
   - `baseSeverity`、`defaultPunishment`、可引用的法律域 / 族 / 组清单。
3. **对象与派生罪名**：同一类行为因对象阶层不同可以形成不同罪名或加重情节。杀人行为加元首对象构成弑君，是独立罪名或 Murder 的加重档，由罪名定义自行登记；同一行为指向不同对象时，基准刑罚与可援引法律随之变化。
4. **运行时匹配**：一桩行为事件携带行为标签 + 对象阶层 + 场景，罪行管理器匹配登记了该行为的罪名定义；一个行为同时落入多个罪名定义时，按对象 / 场景匹配优先与严重性取定。法律不直接引用零散行为标签，只引用罪名定义。
5. **法律反向引用**：法律条目登记 `cited_crimes`（引用哪些罪名定义）。**引用亵渎、异端的是宗教法**（法源域法源族法源组中的宗教法源），不是信仰治理族选项；信仰治理族法律只表达政权对宗教的态度。一条罪名可被多个域 / 族 / 组法律同时引用（走私见 4.8）。`JudicialSystem` 不判断罪名归属，只按当前生效法律对该罪名的引用关系与量刑参数处理。

## 5. 头衔管理器模型（借鉴 TTHTOM 官职三层字段 + CK3 官位字段，层级可扩展）

### 5.0 定位：官职统一归口头衔管理器

TTHTOM 把这一层叫"官职"，我方不再单列官职系统，全部归入**头衔管理器（Title Manager）**。现有 `OfficialOffice` 六值固定枚举只作过渡，最终由头衔定义实体替代。头衔覆盖三类：

- **君主头衔**：元首及其继承、推举产生的最高位；
- **官僚头衔**：执掌机构、具体职权的中枢与地方职位；
- **爵位头衔**：采邑、身份性的位阶名号。

三类共用同一套层级、挂靠、模块、产生方式与资格字段，差异只在模块组合与称谓链。

### 5.1 头衔三段组成（定义层之前先固定语义）

一个完整头衔由三段分开存储，避免把"指代对象、称谓、政权通名"混成一个字符串：

1. **指代对象（authority scope）**：不预设人/地/混合三态枚举，而是一组可空引用字段，标注这个头衔依附于什么文化、族群、法理区域或聚落：
   - `culture_id`：限定文化，可空；
   - `ethnic_group_id`：限定族群，可空；文化与族群的挂靠关系见 5A 节文化系统重构；
   - `region_id`：限定法理区域，可空，见第 8 节；
   - `settlement_id`：限定聚落，可空，地方头衔使用；
   - 多个字段同时填写表示交集；全部留空表示不限定指代对象。
   - 另立"复合头衔"区分：罗马式多头衔同时持有、波斯式兼称多个族群统治者、君合/联统国君主身兼两个政治实体，三者机制不同，在头衔系统专项稿中展开，本节只登记接口位。
2. **称谓（appellation）**：称谓本体（王、宗长、至尊、督军……），是"什么的什么"里的后半段；同一称谓可被不同文化用不同键名实现，走 5.6 的 first_valid 称谓链。
3. **政权通名（realm common name）**：政治体命名是否另取一个通名，是可选项。
   - 有通名：政权以"通名 + 地"自称，如"法兰克王国"；头衔层面另称"法兰克人之王"。
   - 无通名：政权不另设国名形式，只以头衔称谓自称，如"巴比伦之王""苏美尔与阿卡德之王"；古早政权多属此类。
   - 通名与头衔分离：政权命名在生成或变更时决定是否启用通名，不反向改写头衔称谓。

### 5A. 文化、族群认同与传统系统重构（与头衔指代字段联动）

#### 5A.1 CK3 概念取证（先分清，不混用）

- `heritage`（传承 / 遗产）是文化**支柱**：源码实证其实体只存 `audio_parameter`（语音亲缘分组），外观权重在独立 `ethnicities` / DNA 系统，不在 heritage；gameplay 上承担三件事：亲缘分组影响文化接受度、共享 heritage 禁止融合文化、历史起源归类。这三件事被塞进同一个支柱，是我方要拆开、不照搬的原因。
- 文化支柱另含 `ethos`（精神）、`language`（语言）、`martial_custom`（武风）、`head_determination`（首领判定）。
- `traditions`（传统）是挂在文化上、可挑选可替换的条目，分 category：`regional`（地域）、`societal`（社会）、`ritual`（仪式）、`combat`（军事）、`realm`（政权）；带 `can_pick` 条件（地理区域持有比例门槛、heritage 可见条件）、参数、文化 / 人物修正与持有成本（与冲突 ethos 叠加成本）。环境 / 生计类实例：`horse_lords`（草原）、`saharan_nomads` / `desert_nomads`（沙漠）、`himalayan_settlers` / `mountaineer_ruralism` / `mountain_herding`（山地）、`forest_wardens` / `forest_fighters`（森林）、`polders`（海岸圩田）、`caravaneers`（商路）。
- `innovations`（革新）按 era 阶段解锁，提供技术、制度、思想加成；传统可被革新前置约束。
- 文化实体挂载：`ethos`、`heritage`、`language`、`martial_custom`、`head_determination`、`traditions` 列表、`parents` 母文化、`name_list`、`ethnicities` 外貌权重。

#### 5A.1B 学术取证：文化内容与族群认同是两层（Barth → Wimmer 修正）

- **Barth《族群与边界》（1969）**：族群性不由文化内容定义，而由社会组织定义；认同基于归属（ascription）与自我认定，情境依赖、可变；族群边界是社会边界，靠排斥与吸纳的过程维持；文化借用与混合可以持续发生，而族群区分仍靠边界维持——契丹、金吸收华夏文化传统而认同不变，即此机制。
- **Wimmer 多层边界过程理论（2002，Barth 三十年后自修正）**：边界确实优先，但"包裹在内的文化内容"也会反向作用于边界；边界维持是分层过程：国家分类、通婚网络、仪式与谱系建构、语言日常使用分别作用，不合并成单一变量。
- **认同维持机制清单**：内婚规则（边界渗透性的核心阀门，跨族通婚被视为同化最高指标）；制度上的族群分类（金把人口分为女真与"诸色人"）；共同谱系 / 起源记忆；仪式与圣地；语言与称谓；本土地理核心区的保有。
- **人口结构证据（金）**：人口四千余万中女真与契丹合计不足一成，其余为汉人；统治家族长期与汉人士绅通婚、改汉姓、弃母语，朝廷数度下诏用女真文字逆转仍无效；留在东北本土地理区的人群才保留女真语言习俗（"野女真"）。边界瓦解的条件：人口占比极低 + 长期混居通婚 + 失去本土地理基地 + 制度被本地行政体系吸收。
- **草原认同案例（蒙古同盟）**："蒙古"起初只是一个部落名号；成吉思汗以军政联合体（十进制编组、汗号赐封）把方言各异、族属不同的部落纳入同一认同，被征服的蔑儿乞等群体转入"蒙古"认同；反向地，统治集团在钦察草原被本地突厥人口语言同化（突厥化），认同随人口结构与环境条件双向流动。分枝性社会结构下，草原认同融合快、裂变也快（匈奴→突厥→回纥路径重演），高融合与高分离并存。
- **隔绝与文化漂移**：山脉、海洋、河谷垂直带是社会隔绝引擎；互动中断后语言、习俗自主漂移并累积变异；这是文化分离的主因之一。族群认同分离另有独立条件：政权或群体与主体长期隔绝、超过该认同已存续的时长（比例阈值待拍板），边界断裂后认同才可能另立。多数隔绝结局是融合而非分离：本地存在其他文化且力量足够时，隔绝群体被本地文化吸收；只有本地无其他文化或其力量太弱，才自行漂移成新认同。
- **生计类型人类学分类**：采集狩猎；园艺 / 农耕；畜牧（游牧 pastoral nomadism 全移动、转场 transhumance 季节移动、农牧混合 agropastoralism 固定聚落加牧场）；按环境细分：草原马牧、沙漠驼牧、极地驯鹿牧、山地牦牛转场、森林渔猎、海岸渔捞、沙漠绿洲农业、河谷农耕、雨林园艺。环境传统回答"在什么生态里活"，生产传统回答"靠什么活"，二者是两种东西，可同时持有、因子独立。
- **认同下沉度取证（5A.5A 五种历史类型的依据）**：
  - 罗马公民扩散量化（Lavan）：212 年《安东尼谕令》之前行省自由人口 67%–85% 仍非公民；公民不止城市贵族（curial 阶层仅约 1%–2%），经军队、城市官职、解放、皇帝赐姓扩散到部分市民与城镇周边，但远未覆盖全部乡村；论文同时明确警告公民身份不等于认同——公民可能反叛罗马，非公民也可以效忠罗马共同体。拜占庭 *Rhōmaioi* 官方定义是"罗马臣民即罗马人"的法权身份，完整认同另需东正教与希腊语，非希腊语乡村保留本地认同。
  - 中华礼俗边界：华夏以礼俗判别，文化可进；认同话语由士大夫、宗族商人、部分军人承载；编户法律身份把底层纳入王朝秩序，但普通农民的自我指称长期停留在本村本乡，王朝 / 华夏认同是被动接受甚至不自知；国号称谓是朝代性标签，不是稳定族群认同。
  - 西欧封建依附：布洛赫描述下层身份齐一化为"领主的人"（*manicipia*），农民同时属于领主依附关系与村庄共同体；对王权只是遥远想象，王国族群认同下沉要到晚中世纪王权集中、战争动员与方言文学阶段才开始。
  - 阿契美尼德与萨珊的阶层排他：波斯人（Pārsa）是 Briant 所称统治族群—阶级共同体（*ethno-classe dominante*），政策与军职只由波斯贵族把持，巴比伦、埃及、犹太、伊奥尼亚等臣民各自保留本地认同；王室自称阶梯为家族—氏族—波斯人—*ariya* 外层容器。萨珊 *Er / Erān* 是自上而下的国家建构身份，核心准则为信奉琐罗亚斯德教，九成以上底层作为"无名庶民"不被纳入；群山纵横限制全域纵向整合，萨珊只能横向笼络地方贵族，地方族群保留方言与本地谱系。
  - 早期伊斯兰乌玛：宗教共同体跨族群，但等级先按阿拉伯部落谱系排列；非阿拉伯改宗者为 *mawālī*（部族依附客族）；宗教认同可下沉到各阶层，政治与族群认同仍精英化，*mawālī* 人口反超后引发等级紧张与新认同重构。
  - 理论支撑：认同是多层嵌套（家族 / 氏族—村社—地域族群—政权—文明宗教共同体），同一人持有多层、情境激活；精英主导身份建构，大众层多为被动接受或阙如；法律身份、文化内容、族群认同、宗教归属四条线正交但相互作用。

  - 苏美尔城邦：认同核心是城邦本身（乌鲁克、拉格什各自的公民与神庙共同体）；"黑头的人"（sag-gi-ga）是南部族群自称，"苏美尔"是阿卡德人给的他称；渠道为城邦神庙、文字祭祀与王室纪年；口语里苏美尔语消亡后仍作为王权与宗教礼仪语言留存数百年；臣民各自保留本地神庙与商业群体认同。
  - 阿卡德—巴比伦—亚述：王朝把族群标签与政权名绑定；中亚述从"亚述之子"（城邦出身者）改称 *aššurāyū*（亚述人，指代王国全体臣民），是法律身份渠道纵向扩展、认同容器从城邦升到王国的早期案例；巴比伦认同挂在城市与马尔都克崇拜上。

  - 赫梯：多语 diglossia——宫廷与王朝礼仪语言（赫梯楔形文字）与民间通行的卢维语分离；精英认同来自宫廷地位、王朝连续性与书写能力，楔形文字"离开国家赞助就无法存活"；民间通过卢维语象形文字圣像碑铭的可见性识别王室与帝国；语言是认同要素之一但不涵盖认同；精英层与民间层各有一套渠道。
  - 迈锡尼：*Ahhiyawa* 是赫梯对爱琴世界的他称，内部是否存在统一集体认同学界仍有争议；线形 B 行政网络跨多个宫殿，但武士—宫廷精英层之外的认同证据不足，属早期宫殿制精英认同。
  - 古风希腊：三层嵌套——城邦公民（本地出生 + 谱系 + 法律成员资格）、*ethnos* / 方言族群（伊奥尼亚、多利亚，血统 + 习俗门槛）、泛希腊容器（共同语言、共同圣地与节庆、共同习俗、共同起源神话，希罗多德 8.144 四项纽带）；渠道为荷马史诗吟诵、奥林匹亚等节庆集会、方言与贸易；阀门为语言 + 教育（*paideia*）+ 泛希腊仪式；外邦人与奴隶不享公民认同。

#### 5A.2 我方现状问题

- `CultureData` 靠 `parentCultureId` / `childCultureIds` / `allowsBranching` 维护文化树，自身没有族群字段；`EthnicGroupDef` 定义表虽挂靠文化，但运行时未真正接入，族群概念一直闲置。
- 七大考古板块（生计、移动、葬俗、崇拜向量、物质风格、象征焦点、环境适配）直接作为文化独立字段，相似度与融合阻力都在这七维上计算；与传统、革新职责重合。
- `TraditionDef` 已有 `effects`、`incompatibleWith`、`requiredInnovations`、`exclusiveToCultureIds`、`upgradesFrom`，但没有分类分块、阶层门槛、倾向因子、固化强度字段；环境清单笼统把平原算作一类，没有同生态亚型，也没有条目级共存 / 互斥规则。
- 分离 / 融合只有 `CultureSimilarity` 的相似度、分离 / 融合阻力静态公式，未与传统倾向挂钩。
- 现状没有族群认同实体与认同边界状态变量：认同分离、认同吸纳、认同同化全部未计量；文化转变进度与认同转变进度混在同一条通道里，未分开。
- 第一批骨架口径下认同只按单一实体挂载，没有嵌套层级（内层地方认同 / 外层文明容器）、没有角色下沉度与持有状态（Active / Passive / Absent），精英与底层被默认同层一致；也没有渠道与边界阀门的区分（见 5A.5A）。
- 第一批骨架照搬了 CK3 `HeritageDef` 支柱，按 5A.6 复核为概念混用，待撤场拆分。

#### 5A.3 目标模型

**实体层级（认同与文化分开两层，不再设"文化族"次级归类）**：

- **族群认同（Ethnos）**：归属意识与边界——自我称谓、谱系 / 起源记忆、通婚规则、仪式边界、制度分类；边界由社会关系维持，不由文化内容维持；一个族群认同可挂靠多个具体文化，文化之间借改而认同不变。
- **文化（Culture）**：可观察内容——传统条目、语言、习俗、器物、仪式实践；可借用、可替换、可混合。语言挂文化；ethos 作文化精神气质；传统列表挂文化。
- 个人身上同时持有两个归属：他认同哪些族群认同（ethnic identity，可多层嵌套，见 5A.5A）、他遵循哪个文化（culture）；二者可不同步（契丹文化上吸收汉俗、认同上仍是契丹）。

**传统分块 `category`（原"居住"改名"环境"）**：

- 底层生产生活：
  - **环境传统（Environment）**：在什么生态里活，分两层——大区生态（草原、沙漠、山地、森林、冲积平原、旱作高原、沿海平原、河谷、河口三角洲、海湾潟湖、海岛、湖盆、苔原、雨林、戈壁等），同一大区生态下再分适应亚型（如森林里有狩猎型、采集型、林缘游耕型；草原上有牧马型、绵羊型；山地里有高山牧场型、林山型）；平原不能笼统合并：大河冲积平原、黄土旱原、沿海平原、草原平原、丘陵谷地各是各的生态；
  - **生产传统（Production）**：靠什么活——游牧、畜牧、转场、农牧混合、农耕、园艺、渔捞、采集狩猎等生计策略。环境与生产是两种东西，可同时持有、因子独立。
- 上层建筑：政治传统（组织、治理、身份秩序）；部分政治传统有阶层门槛，晋升到某阶层后才允许启用。
- 仪式、思想类传统沿用 CK3 `ritual` / `societal` 思路继续细分，清单待拍板。

**环境传统的共存与互斥（不设"混合型"硬字段）**：

- 多个环境传统可以同时挂在一个文化上，组合本身就是常态；不设"混合环境"枚举占位，由条目共存表达。
- 可共存（生态互补或垂直分带）：山地转场牧场 + 河谷农耕（同一社群冬夏垂直移动，或同一政权内分社群持有）；绿洲农耕 + 沙漠驼牧（城镇定居与商队 / 游牧队并存）；海岸渔捞 + 沿海平原农耕；森林采集渔猎 + 林缘游耕；河口渔捞 + 三角洲农耕；湖盆渔捞 + 盆地旱作；冲积平原农耕 + 河口三角洲渔捞。
- 互斥（同一聚落、同一人群无法同时维持），分层声明：
  - 环境层：苔原与雨林、沙漠与雨林、深海大洋环境与山地内陆环境互不相邻；
  - 生产层：全移动草原游牧与固定聚落农耕不挂在同一人群（可同政权分属不同社群）；苔原驯鹿畜牧与雨林园艺、定居农耕互斥；沙漠绿洲灌溉农耕与雨林游耕互斥；
- 规则承载：互斥对由条目现有 `incompatibleWith` 字段声明，互补对由新增 `complementWith` 字段声明，不在代码里写死一张全局混合表；同层传统共存时因子按方向加减，反方向因子不相加。
- 环境传统与生产传统分别声明各自的互斥关系：两个生产传统是否互斥（如全移动游牧与定居农耕）与两个环境传统是否互斥，分开判断。

**地理可见条件：复用现有地块与群系字段，不另造地貌枚举**

- 环境传统的候选可见条件直接读 `TileData` 现有字段：`biome`（`GameEnums.BiomeType`，A 低水沃野 / B 高地硬骨 / C 极端覆盖与过渡 / D 海洋四系约百值）、`oceanTier`（`None/Land/Coast/NearSea/MidSea/FarSea/DeepSea`）、`isRiver`、`waterAdjacentWeight`、`climateZone`、`elevation01`、`slopeDegree`；不新建一套地貌枚举与群系定义。
- 条目声明方式：传统定义内挂 `biomeTags`（可用 `BiomeType` 键列表或群系大区号 `A/B/C/D` + 亚型键两类写法）、`oceanTierMin`（水域传统起步档位）、`requiresRiver` / `waterAdjacentMin`；候选过滤时取文化所在地块群系集合做命中判断，与 5A.4 的阶层门槛、前置革新、互斥过滤串联。
- 映射原则：草原条目挂 `TemperateGrassland` / `Savanna` / `Parkland` 与草原平原类群系；荒漠条目挂 `HotDesert` / `InlandDesert` / `CoastalDesert` / `ErgSea` 等；绿洲单列 `DesertOasis` / `HotSpringOasis`；山地按海拔与林段拆 `AlpineMeadow` / `HighMountains` / `FoldMountains` 与 `KarstMountains` / `CloudForest` / `TemperateMixedForest`；森林按林型拆四类；平原五条分别映射 A 系冲积 / B 系沿海与黄土 / C 系草原；水域条目按 `Estuary` / `Delta` / `Lagoon` / `Fjord` / `EndorheicLake` / `CalderaLake` 与 `OceanTier` 档位；海岛条目挂 `VolcanicIslands` / `ContinentalIslands` / `CoralAtoll` 等岛系；逐条群系集合已在 5A.7 清单标注归属方向，JSON 落地时照单填 `biomeTags`。
- 水域档位以地块 `oceanTier` 七档为准：`Coast` / `NearSea` 配沿岸渔捞，`MidSea` 配近海贸易与航线传统，`FarSea` 配远洋传统，`DeepSea` 不作可居住环境传统；`OceanZoning.OceanZone` 是距离场内部五档编码（Land / Coast / Neritic / Oceanic / DeepSea），不直接进传统条件，实现时由距离场换算到 `oceanTier`。
- 5A.9 法理区域就位后补的是"文化 / 族群 / 区域持有比例"类运行时条件；地块生态条件不依赖区域系统。

**移动性由环境与生产组合推导，不是单一传统决定**：

- 草原游牧（草原环境 + 游牧生产）：移动性极高；沙漠驼牧：移动性高；山地转场：移动性中；河谷农耕：移动性极低；森林采集渔猎：移动性中低。移动性、分离倾向、融合倾向三个因子取环境传统与生产传统因子的同向叠加：同方向因子相加、反方向不相加，聚合后按现有 `GetFactorSum` 路径 `Clamp01`（定居程度）或 `Clamp[-1,1]`（因子相近度），不简单取大，也不另设环境 / 生产权重系数。
- 四种组合的文化关系（生活方式相近度，不等于认同距离）：游牧—游牧生活方式最近、文化可相近且边界柔性，易互纳也易裂变；农耕—农耕传统相近、认同稳固，融合慢但融合后不易再裂；游牧—农耕生活方式差距最大，文化相似度低，政治体内部张力高。

**七大板块撤出 `CultureData`，改由革新推导**：

- 现状七字段不再作为文化直接分类；相关内容由对应革新持有程度与传统因子推导。
- 传统受革新制约：持有前置革新才能持有传统（沿用 `requiredInnovations`）；反向固化：关联革新研究程度越高，该传统越固化、替换成本越高。
- 传统增加影响因子 `factors`：物产偏好、分离倾向、融合倾向、定居 / 农耕程度评分等，单条强度分弱 0.1 / 中 0.2 / 强 0.3；不同类别传统可以共存；同类互斥由条目现有 `incompatibleWith` 声明（环境层与生产层分别校验，规则见 5A.3"共存与互斥"段），同类共存因子按上一段同向叠加规则合成，不再另设待拍板项。

**转变分两套独立通道：文化转变与认同转变**：

- **文化转变（传统、语言、习俗层面）**：个人层面人物改文化（通婚、迁居、身份转变），门槛低；群体层面聚落或地块文化转变，门槛更高，由环境 / 生产传统因子与融合阻力共同约束。
- **认同转变（族群归属层面）**：独立于文化转变，门槛公式见 5A.5，下沉度与嵌套参数见 5A.5A；个人改认同与群体认同转移分别计进度。

**分离与融合倾向规则（由传统因子合成，不另设独立数值）**：

- 定居农耕程度越强的两个文化，越难合成同一族群认同；
- 定居农耕文化分离倾向弱；游牧文化分离倾向最强，同时融合倾向也最强；
- 环境传统可以共存：沙漠与绿洲同时存在时，两种环境传统的倾向因子相互加减；可共存与互斥的具体对组由条目字段声明，规则见上"环境传统的共存与互斥"段；
- 传统可以被其他文化学习、更改或替换；**认同分离倾向与文化分离倾向分开计量**，族群认同更保守，具体系数待拍板。

**文化实体挂载字段**：`ethnicGroupId`（族群认同键）、`languageId`、`ethosId`、traditions 列表、`parentCultureId`（母文化分离谱系）、名字表；`heritageId` 的处置见 5A.6；七大板块字段迁出，由革新与传统推导。

#### 5A.3A 姓名制度：法律规制层 + 文化习俗层（起点默认单名）

**历史序位（演化起点，不是静态并列选项）**：

- 世界起始时所有人只有一个本名，没有任何附加名；重名只能靠临时性口头称呼区分——绰号、地望、父名、职业或部族归属，这些称呼不固定、不世袭，人离开原地或事件过去就可能消失。
- 固定的世袭标识很晚才出现，而且先属于贵族：早期只有统治家族、有封地者拥有可以世代沿用的氏 / 家名，平民有名无氏；这对应"氏所以别贵贱"的身份秩序，不是全民通行制度。
- 全民固定姓是政权法律规制的结果：为了在户籍、税册、军籍、契约与法庭记录里固定区分每个人，政权颁布规则要求统一使用固定姓氏与继承线；法律推行若干代之后，这套由法律产生的标识才固着成文化传统。没有行政登记需求的社会，长期停留在单名 + 临时代号的状态，不等于"配置缺失"。

**参考取证**：

- CK3：本名从文化名池取，家族名来自 dynasty，父名作可选中间名；它只覆盖"世袭姓 + 可选父名"一种后世组合，没有表现姓氏从无到有、先贵族后全民的演化过程，我方不照搬其默认假定人人有姓。
- 欧洲中世纪：诺曼贵族带入世袭家名；多数平民长期使用由职业、父名、地望、绰号构成的 by-name，人头税、庄园卷宗、教区登记等行政记录要求每人名下固定不变，by-name 才逐步变成世袭姓。
- 先秦中国：姓别婚姻、氏别贵贱，有土者有氏，平民有名无氏；秦汉以后姓氏合流，贵族标识扩散为通用标识。
- 近代案例：日本 1875 年苗字必称义务令由兵籍调查需要推动，强制国民有姓；全民固定姓的直接动因是兵役与登记，不是文化自然演化。

**两条线，分开归属**：

1. **法律规制层——境内治理域·身份族·姓名登记组（见 4.8）**：回答政权如何固定身份标识、为哪些人群固定、按什么线继承、用于什么登记、能不能改。档位：
   - 固定标识范围：无固定标识（默认）/ 仅贵族世袭氏 / 全民固定姓；
   - 继承线：父系 / 母系 / 双系 / 自选；固定标识为"无"时本组继承线不生效；
   - 登记用途开关：户籍 / 税册 / 军籍，标明固定姓被用于哪些行政记录；
   - 改姓与赐姓许可：禁止 / 特许（政权可赐姓）/ 自由；
   - 婚名归属：保留本姓 / 从夫姓 / 从妻姓 / 双姓。
   - 开放"全民固定姓"需先持有户籍、税册或军籍类革新；仅贵族世袭氏不需要行政登记革新。
2. **文化习俗层——日常称呼方式（挂文化）**：回答人们平时怎么称呼彼此；它可以与法律固定标识不同步：法律要求登记固定姓的社会，日常仍可能习惯单名、父名或绰号相称。

**文化习俗主档 `AddressCustom`（七值，默认单名制）**：

| 键名 | 参考名 | 日常全名结构 | 说明 |
|---|---|---|---|
| `Mononym` | 单名制 | 仅本名 | 默认档；不生成日常附加名，重名靠语境、头衔或临时绰号区分。 |
| `Patronymic` | 父名称呼 | 本名 + 父名派生 | 父名前后缀或父系名链，逐代更替；不形成固定家族姓。 |
| `Matronymic` | 母名称呼 | 本名 + 母名派生 | 派生线为母系；与父名称呼互斥为主选。 |
| `ClanName` | 氏族称呼 | 本名 + 氏族 / 部族名 | 日常以氏族集团名相称，不另立家族姓。 |
| `ChainName` | 父子连名 | 本名与父名部件相接成链 | 按连名规则取父名部件接入本名，世代相接。 |
| `StackedName` | 多层叠称 | 本名 + 可选亲从名 / 父名 + 名号 + 部族 / 地望 / 职业名 | 部件按开关启停、可叠加；部件缺省时不占位。 |
| `FixedHouseName` | 世袭家名称呼 | 本名 + 固定家名 | 法律固定标识已固着为日常习俗后启用；未固着前不选本档。 |

**文化习俗附加开关**：排行部件、名号层（绰号 / 荣誉名，事件功绩派生可更换）、亲从名层、家名上叠父名中间名（仅 `FixedHouseName` 档可用）、避讳禁称（礼仪 / 宗教场合不以本名相称，只影响显示与称谓，不改动本名记录）。

**部件词表（挂语言 / 文化包，空表即不生成该部件，不回退姓氏池）**：本名池男 / 女；父 / 母名前后缀；氏族名池；连名截取与相接规则；名号前缀 / 后缀与绰号池；地望 / 部族 / 职业归属名部件；部件顺序、前后缀位置、连写还是空格由语言规则表统一配置。

**演化与固着规则**：

- 出生默认只有本名；法律未要求固定标识时，人物不生成家族姓。
- 法律姓名登记组推行固定标识后，登记名按法律规则生成并继承；日常称呼仍按文化习俗走，两套名字并存。
- 固定标识在同一法律规则下存续若干代、且文化相关传统固化强度达到阈值后，固着为文化习俗：文化主档才允许选 `FixedHouseName`，日常称呼改用固定家名。
- 法律被废除后，未固着的登记名可以回落；已固着为习俗的部分按文化转变机制缓慢淡化。
- 贵族世袭氏先于全民固定姓出现；氏名与家族轨、头衔称谓衔接，不自动进入平民日常称呼。

**数据字段与生成规则**：

- `CharacterData` 恒存 `givenName`；其余部件可空：`houseName`（法定世袭氏 / 固定姓，法律未要求时为空）、`patronymic`、`clanName`、`epithet`、`teknonym`、`birthOrderPart`、`nisbaName`、`extraGivenNames`。
- 两套展示名由独立 `NameComposer` 生成：`legalName` 按法律姓名登记组规则拼登记文书、税册军籍、正式头衔用名；`everydayName` 按文化习俗主档与开关拼日常称呼；二者可不同。
- 家族节点只在法律要求固定标识时保存 `houseName`；父名 / 母名 / 连名习俗下家族不保存固定姓。
- 人物内部持久化键名与登记名、日常名都分离：改姓、赐姓、授号、婚名、转文化都不改变持久化键名，规则见第 7 节。
- 同一聚落、同一阶层本名不重复的过滤归入第 7 节命名过滤。

**边界**：日常称呼方式归文化传统；固定标识范围、继承线、登记用途、改姓赐姓、婚名归法律身份族；名号与荣誉称号成为稳定头衔后转入第 5 节头衔体系，不长期留在人名部件里。

**待拍板**：法律姓名登记组各档具体措辞与前置革新清单；文化习俗各档前后缀词表与连名规则样板；固着所需代数与固化强度阈值；名号层启用条件（年龄 / 功绩 / 阶层门槛）；排行部件在哪些习俗档启用；避讳开关显示规则；贵族世袭氏的授予与回收规则。


#### 5A.4 接口与改造点

- 头衔指代的 `ethnic_group_id`、`culture_id` 直接引用本系统；7.3 节命名过滤里的文化、族群、语言条件也从本系统取值；认同层就位后，指代条件再分列认同键与 `cultureId` 两套；认同查询按嵌套层级命中（人物持有任一内层 / 外层认同即通过）；下沉度状态（Active / Passive / Absent）作为头衔、官僚资格、派系归属的只读参照，不做硬性排除，硬阀门仍走 `boundaryValves`。
- `CultureSimilarity` 的相似度、分离阻力、融合阻力改为读取传统因子与革新持有度，替代现有七维硬编码权重；认同距离另走 5A.5 通道，不并入文化相似度。
- 传统候选过滤：`ListTraditionCandidates` 除阶层门槛、前置革新外，再过条目级 `incompatibleWith` 互斥对组；`complementWith` 只标注生态互补提示，不作为硬门槛；环境层互斥与生产层互斥分别校验。
- 姓名制度接口：法律身份族·姓名登记组提供固定标识范围、继承线、登记用途、改姓赐姓、婚名归属；文化包登记 `AddressCustom` 日常称呼主档与附加开关、部件词表；`CharacterData` 恒存 `givenName`，其余部件可空，由 `NameComposer` 分别拼 `legalName` 与 `everydayName`；现状 `firstName + lastName` 的散点拼接（继位、世界生成、家族调试、封圣）统一改走 `NameComposer`；家族节点 `houseName` 仅在法律要求固定标识时保存，不再无条件继承父姓。

#### 5A.5 认同转移与分离模型（独立于文化转变的第二条通道）

**两层归属并存**：人物同时记录 `cultureId`（遵循的文化）与认同列表（认同的族群归属，可多层嵌套，见 5A.5A）；聚落、地块、政权持有群体认同。文化转变改前者，认同转移改后者，进度与门槛公式互不替代。

**认同边界状态变量（挂族群认同实体）**：

- `endogamyTendency`：内婚倾向，边界渗透性阀门；内婚越强，跨族通婚越难、认同稀释越慢；
- `classificationStrength`：制度分类强度（如法律把人分为本族与诸色人），制度边界在则认同维持几代；
- `memorySolidity`：共同谱系 / 起源记忆与仪式的固化度；
- `coreTerritoryHeld`：本土地理核心区保有度，丢失核心区是边界瓦解的信号之一；
- `nestedParentId`：外层容器认同键，可空，支持 5A.5A 嵌套层级；
- `reachByRole`：五阶层 `SocialClass` → 持有状态（Active / Passive / Absent）映射，键复用 `CharacterData.RoleToClass` 现有映射，同一认同在不同阶层下沉程度不同；
- `salienceByRole`：五阶层显著度权重（0–1），决定该层认同在日常决策与称谓中的激活优先级；
- `accessChannels`：渠道集合，键为 `IdentityChannel` 六值（LegalIdentity / Army / CommunityNetwork / Education / KinshipMarriage / OfficialMedia），每条带 0–1 初始密度；
- `boundaryValves`：阀门集合，键为 `IdentityValve` 五值（Bloodline / LegalMembership / ReligiousConversion / CulturalLanguage / RitualParticipation），每条带 0–1 开放度，硬约束不过阀不入 Active。

**动态一：吸纳——征服者认同扩张（蒙古模式）**：

- 前提：同盟式军政体制、名号赐封机制、通婚门槛放开；被纳入人口在数量上不构成多数。
- 进度变量：统治认同人口占比、制度整合度、通婚率、世代数、共同仪式与谱系建构进度。
- 路径：被征服部落成员先在个人层转入统治认同；群体认同转移需要数代人加上制度与仪式固化，不是一次征服完成。

**动态二：同化——少数统治者被多数本地人同化（突厥化、女真上层模式）**：

- 前提：统治族群人口占比极低、长期定居本地、混居通婚、失去本土地理核心区、制度被本地行政体系吸收。
- 路径：先在统治家族个人层发生认同转向（通婚、子女教育、本地任职网络），群体认同转移滞后数代；阈值（占位，待校准）：人口占比低于临界值 + 定居程度高 + 通婚率越过水位线 + 世代数累加；本土核心区未丢失时认同可由制度边界勉强维持（金朝前期），核心区丢失或制度被本地体系吸收后加速瓦解。
- 反向校验：留在本土地理环境中的支系（"野女真"）保留原语言习俗与认同。

**动态三：认同分离**：

- 条件：群体与主体政治体长期隔绝，隔绝时长超过该认同已存续时长（比例阈值待拍板，可缩小）；政权长期分立；日常社会互动中断。
- 新认同生成：认同分离成立时自生成新的族群认同实体（参照文化分离谱系接口），原实体分裂为两支；不与文化融合流程混用。
- 大多数隔绝结局是融合而非分离：本地存在其他文化且力量足够时，隔绝群体被本地文化吸收；只有本地无其他文化或其力量太弱，才自行漂移成新认同。
- 认同分离与文化分离分开计量：认同分离靠边界断裂与时间积累；文化漂移（语言、习俗）由日常互动频率与交通可达性决定，传统固化强度决定替换成本；认同分离不必然伴随文化分离，两者进度独立。
- 三条动态的转移阻力都要按角色档与持有状态加权（见 5A.5A）：Active 层掌握谱系叙事、转向阻力最高；Passive 层只在渠道覆盖下维持，渠道撤除后先退回 Passive，再退回 Absent；Absent 层本来就没有高层认同可转移，其认同转向只涉及内层本地归属。

#### 5A.5A 认同下沉度、嵌套层级与历史类型模板

**最小单位：个人自指**

- 认同的最小单位是"我认为自己是什么人"，不是部落、不是地域、不是政权标签；同一个人可以同时持有多层认同，情境不同激活不同层。
- 四条线正交：法律身份（公民 / 成员资格）、文化内容（语言、习俗、传统）、族群认同（自我归属与边界）、宗教归属。彼此相关但不等价：持有法律身份不必然认同（行省公民参与叛乱），没有法律身份也可以想象自己属于更大共同体（非公民效忠罗马）。

**嵌套层级（nested identities）**

- 自内向外：家族 / 氏族 → 村社 / 地方群伙 → 地域族群 → 政权 / 封国 → 文明—宗教共同体。层间不是树状隶属，而是多层并列挂靠；高层容器可以覆盖多个内层（伊朗语各族共享外层 *ariya* / 伊朗标签，内层各自保留自称）。
- 认同实体记 `nestedParentId`（外层容器，可空）；人物持有认同列表而不是单一 id；每条认同单独记录持有状态与显著度。

**下沉度：角色分层 × 持有状态三档**

- 角色分层不另造新映射：直接复用现有 `CharacterData.RoleToClass(CharacterRole)` 的五阶层——`Royalty`（Ruler/Heir/Spouse）、`NobilityClergy`（Noble/Clergy/Courtier/Military）、`MerchantFreeman`（Merchant/Scholar）、`Peasant`（Commoner）、`Slave`（依附民 / 奴隶，无角色档对应，由人口块 `PopulationBlock.socialClass` 表达）；`reachByRole` 以这五阶层为键，九档 `CharacterRole` 通过现有映射归并。政治传统门槛排序继续用 `TraditionElevation.Rank` 现有九档（Commoner 0 / Spouse·Heir·Courtier 1 / Merchant·Military·Clergy·Scholar 2 / Noble 3 / Ruler 4）。
- 持有状态三档：`Active` 主动认同（会自我表述、掌握谱系与高层叙事）；`Passive` 被动接受（知道归属、能被归类，但不主动使用、不掌握高层叙事）；`Absent` 阙如（只知直接领主 / 村社 / 本部族，对更高层级认同没有概念）。
- 同一个认同实体对不同角色档的下沉状态不同：同一政权认同在王室是 Active，在官僚军人是 Active 或 Passive，在农民可能 Passive 甚至 Absent。

**渠道机制（认同靠什么下沉，不默认全民同层）**

- 法律身份渠道：户籍、公民法权、赋税军籍登记；
- 军队渠道：老兵安置、军籍、同盟部族；
- 共同体网络：城市议事会、教区 / 寺坊、村社法庭与集体仪式；
- 教育与文书渠道：识字、经典学习、语言培训；
- 家族与婚姻渠道：贵族联姻、赐姓、谱系建构；
- 官方媒介渠道：钱币铭文、碑刻、官方称谓、集体节庆仪式。
- 渠道密度与覆盖角色范围决定下沉度；渠道随法律、革新、制度变化增减，渠道撤除后上层认同先退回 Passive，再退回 Absent。

**边界阀门（认同准入条件组合，挂认同实体）**

- 血统 / 内婚；法律成员资格；宗教皈依；文化语言习得；仪式参与。多阀门可同时启用，硬约束：不过阀门不进入 Active 档；阀门本身不受认同转移权重影响。

**五种历史类型模板（参考参数组合，不是硬编码文明标签；架空实体由制度、渠道、法律自然合成）**

1. **罗马—拜占庭式：法权身份纵向扩散，宗教语言双重门槛**
   - 罗马：公民身份经军队、城市官职、解放、皇帝赐姓扩散；212 年《安东尼谕令》之前行省自由人口估计六七成以上仍非公民，公民也超出城市贵族但远未覆盖全部乡村；官方后来"罗马臣民即罗马人"的法权定义只在表层覆盖全境。拜占庭：官方话语臣民即 *Rhōmaioi*（政治 / 法权定义优先），完整认同需要东正教 + 希腊语；非希腊语乡村与被征服行省保留本地认同。
   - 渠道：法律身份、军队、教会教区、语言教育；阀门：法律成员 + 宗教 + 语言。
   - 下沉：王室官僚军人 Active；城市自由人 Active 或 Passive；西部拉丁化乡村部分 Passive；东部非希腊语乡村 Absent，本地认同主导。
2. **中华式：礼俗边界 + 士大夫承载叙事 + 编户法律身份**
   - 华夏认同以礼俗为界，文化可进（夷狄进于中国则中国之）；认同话语由科举士大夫、乡绅宗族、商帮修谱、部分军人生产；编户齐民的法律身份（户籍、赋税、徭役、里社祭祀）把普通人纳入王朝秩序，但多数农民只持有本村本乡认同，王朝 / 华夏认同是被动接受甚至不自知；国号称谓（某朝人）是朝代性标签，不是稳定族群认同。
   - 渠道：士人教育与网络、宗族乡约、编户法律身份、军籍、商帮；阀门：礼制文化 + 文教（后天习得为主）。
   - 下沉：士人 / 官员 Active；宗族与商人 Active 或 Passive；军人部分 Active；普通农民 Passive（经编户、里社、歌谣间接触及）；边远未编户地区 Absent。
3. **西欧封建式：依附关系与村社共同体双层，上级认同遥远**
   - 农奴首先是"领主的人"（人身依附世袭），同时是本村社成员；对国王与上层族群认同只是遥远想象，靠加冕神圣化、圣徒崇拜、战争动员间接触及；王权 / 族群认同的下沉是晚中世纪王权集中、方言文学、长期战争之后的事。
   - 渠道：领主司法依附、村社法庭与敞田共同劳作、教会教区（宗教认同覆盖全阶层）；阀门：依附关系 + 宗教共同体。
   - 下沉：最高层级 Active 仅诸侯与骑士；商人与城市居民在方言与城市网络下渐次 Active；农民对本领主 / 村社 Active 或 Passive，对王国 Absent；宗教认同跨阶层，但不等于族群认同。
4. **萨珊—波斯式：横向精英整合，顶层认同不下沉**
   - 阿契美尼德：波斯人（Pārsa）是统治族群—阶级共同体（*ethno-classe dominante*），军职与政策位置只由波斯贵族把持；巴比伦、埃及、犹太、伊奥尼亚、粟特等臣民各自保留本地认同；王室自称阶梯嵌套：家族 → 阿契美尼德氏族 → 波斯人 → *ariya*（外层，覆盖伊朗语各族，不等同人口普查类别）；波斯平民同样处在底层，族群身份不保证地位。
   - 萨珊：*Er / Erān*（伊朗人）本是阿维斯陀神话社群，核心准则为信奉琐罗亚斯德教；自上而下的国家建构身份，阶层排他极强，九成以上底层是"无名庶民"，不被纳入"伊朗人"；群山纵横限制全域纵向整合，只能横向笼络地方贵族；地方族群（吉兰人、德莱木人、马赞达兰、呼罗珊等）保留方言、本地谱系与异教 / 分裂教派；官方媒介为钱币、多语碑刻、贵族年度集会仪式。
   - 渠道：贵族联姻与世袭封地、王权—宗教等级、官方仪式；底层通道几乎没有；阀门：血统贵族 + 宗教 + 仪式出身。
   - 下沉：只有王室与大贵族 Active；地方附庸贵族 Passive；农民与依附民对"伊朗人"认同 Absent，只认本地村社、部族与领主；伊斯兰早期后呼罗珊、中亚、里海地方王朝重新建构地域认同。
5. **早期伊斯兰式：乌玛宗教共同体跨族群，部落谱系定等级**
   - 乌玛以宗教共同体跨越族群，但社会等级先按阿拉伯部落谱系排列；非阿拉伯改宗者为 *mawālī*（依附某部族的客族），身份是部族附属而不是平等成员；宗教认同（清真寺、教法、阿拉伯语、礼拜共同体）可下沉到各阶层，政治与族群认同仍精英化；改宗 + 部族依附是阀门；后来 *mawālī* 人口超过阿拉伯人，引发等级紧张与新认同重构（舒乌比耶式文化运动）。
   - 渠道：清真寺与教坊、教法学习、语言、部族依附契约；阀门：宗教皈依 + 依附契约。
   - 下沉：宗教认同跨阶层 Active 或 Passive；阿拉伯部落贵族 Active 于政治族群认同；非阿拉伯 *mawālī* 对阿拉伯部族认同 Passive 或 Absent，只在宗教共同体层形成 Active 归属。

**同语族内外层关系（伊朗案例展开）**

- 外层标签是王室与精英使用的高阶容器，对内是文化—语言亲缘分组（通婚亲和、文化接受度通道，见 5A.6 `affinityGroup`）；内层地方认同各自有自我称谓、谱系与排他边界；二者并存，不要求内层先放弃本地认同才被纳入外层。
- **称呼与认同分开**：官方碑铭、文书、贡使队列使用的族群称谓首先是王权分类，不等于被称呼者的自我认知；内层认同的排他性看内婚、宗教、谱系、方言、仪式参与，不看外层标签的覆盖范围。阿契美尼德时期王室碑刻把波斯、米底、帕提亚、巴克特里亚、粟特、伊奥尼亚、埃及、巴比伦等并列收入部族清单，清单是王室对自己的描述，不是一套全民统一认同；萨珊时期 *Erān* 作为容器收拢贵族层，内层地方认同（吉兰人、德莱木人、马赞达兰人、呼罗珊地方人群等）没有被取消，各自保留方言、谱系与仪式边界。
- 游戏处理：一个文化可挂靠外层 `affinityGroup`；一个人物可同时持有内层认同与外层认同；外层认同的 Active 状态默认只在精英与神职人员层，农民层要么 Passive 要么 Absent。

**已定（对齐现有代码，不再待拍板）**：角色分层映射复用 `CharacterData.RoleToClass` 五阶层，政治门槛排序复用 `TraditionElevation.Rank` 九档；因子与阈值沿用 5A.3、5A.4 现有聚合与常量。

**待拍板**：嵌套层数上限；五型模板默认下沉状态表的微调数值；渠道增减对状态迁移的速度参数；宗教共同体认同是否单列一种边界阀门；外层认同是否可脱离政权单独存续。

#### 5A.5B 历史沿革分层：最早可考形态与演化方向

**定位**：5A.5A 五型是成熟政权的参数组合；本节按最早文献与考古记录分层，列认同形态的演化起点与方向。游戏不硬编码青铜时代、古风时代、中世纪之类阶段标签，形态由渠道、阀门、制度组合自然合成；时间参数只用于世界生成初期默认值。

**第一层：城邦—王朝型（历史溯源：青铜时代城邦与王朝）**

- 容器：城邦或王朝直接挂族群标签；渠道为神庙、军队、王室纪年与官方文书；阀门为土地归属、礼制与王室身份。
- 案例要点：苏美尔以城邦为认同核心，"黑头的人"是南部自称、"苏美尔"是他称；亚述认同容器从"亚述之子"（城邦出身）升到 *aššurāyū*（王国全体臣民）；埃及以秩序与混沌的他者观划界，画像服饰肤色是图像标签，雇佣兵安置是吸纳渠道；赫梯为宫廷礼仪语言层与民间卢维语可见性层双层认同；迈锡尼是宫殿制武士—宫廷精英认同，统一集体认同证据不足；腓尼基居民只认本城邦公民身份，共同语言、贸易网络与神祇谱系构成松散外层，殖民城邦另立 Punic 容器；伊特鲁里亚十二城以共同宗教节庆联盟，政治各自独立，语言、墓葬与占卜习俗是边界；米诺斯自我称谓不可考，只能从宫殿与器物推断共同体层级。
- 下沉度：精英、武士、宫廷书吏 Active；市民与神庙依附者 Passive；乡村、被征服人群 Absent 或本地认同主导。

**第二层：城邦与祭祀等级并列（历史溯源：古风时代城邦与祭祀部族）**

- 容器分化方向：希腊式城邦公民 + 方言 *ethnos* + 泛希腊容器三层并列；早期罗马为家族—*gens*—*curia*—部落嵌套公民；吠陀为部族—氏族之上的祭祀等级容器；早期以色列为十二部族段裂之上的盟约宗教容器，阀门为盟约、起源谱系与仪式律法。
- 渠道：出生谱系、法律成员资格、集会节庆、教育、祭祀资格；阀门为出身谱系、语言、仪式资格。
- 下沉度：公民、武士、祭司 Active；自由居民 Passive；依附人口与被征服者 Absent。

**第三层：部落群与政治联合体型（历史溯源：日耳曼、凯尔特、斯拉夫、阿拉伯、突厥、斯基泰等部落群）**

- 容器：基层部族、氏族、村社是 Active 层；外层亲缘或政治联盟容器松散，Active 只在首领与战士层；政治联合体可在战争联合中吸纳、重组，不等于血缘统一体。
- 渠道：口头谱系、战时首领、血亲义务、集会、祭司或吟游网络；阀门为血亲谱系、誓约、仪式习俗。
- 排他性：政权标签与语言族群可以不重合（突厥人不称其他突厥语族为 Türk；斯基泰自称只指王族核心，波斯 Saka 与希腊 Skythai 是覆盖整个草原语群的他称；*Germani*、*Keltoi*、Antes 都是他称）；联合瓦解后外层容器快速退回 Passive / Absent，内层认同保留最久。
- 西周春秋是向礼制容器过渡的中间态：国人 Active、野人 Passive，阀门为礼制而非血统，接 5A.5A 第 2 型中华式。

**演化方向（参数迁移，不设硬性阶段枚举）**

- 渠道：血亲与仪式 → 法律身份 → 军队 → 教会或教育 → 官方媒介；渠道扩张带动下沉度从精英层逐步下移。
- 阀门：血统出身 → 文化习得、法律资格、宗教皈依；开放度随制度变化，不单向进步。
- 容器：城邦或部族 → 政权 → 文明宗教共同体。
- 可逆性：政权瓦解或渠道撤除时，外层认同先退 Passive 再退 Absent，内层部族、村社认同保留最久。
- 同一世界内不同形态并存：草原部落群、城邦、官僚王朝可以同时存在，不按全球统一时间线推进。

**初始参数（对齐现有代码枚举与阈值，世界生成默认值，运行时随渠道与制度演化，不写成文明标签）**

- 复用代码现状：阶段锚点用 `GameEnums.CultureStage`（Band / Tribe / Chiefdom / EthnicGroup / HighCivilization），政权形态锚点用 `RealmForm`（Sedentary / SemiSedentary / Nomadic）；角色下沉用 5A.5A 已定的五阶层 `RoleToClass` 映射；人口阈值沿用 `CultureStageEvolutionSystem` 现有常量（100 / 1000 / 5000 / 10000），分层与专业化阈值沿用 0.2 / 0.5 / 0.7 与 0.3 / 0.5，不另起一套数字。

#### 5A.6 heritage 处置：取消独立支柱，拆分归位

- CK3 源码实证：`heritage` 实体只存 `audio_parameter`（语音亲缘分组），外观权重在独立 `ethnicities` / DNA 系统；gameplay 上又兼任亲缘分组、融合禁止门槛、历史起源归类三件事，是概念混用的来源，我方不照搬。
- 拆分归位：
  - 亲缘分组（通婚亲和、文化接受度、融合距离）→ 迁入族群认同实体的 `affinityGroup` 字段；
  - 外观 / 血脉标签 → 归 `RaceData` / 外观层，不留在文化系统；
  - 起源归类与谱系记忆 → 归族群认同实体的谱系 / 记忆字段；
  - 独立 `HeritageDef` 支柱取消：上一轮骨架中的 `HeritageDef` 标 `[Obsolete]` 待删，`CultureData.heritageId` 同步废止；`affinityGroup` 迁移到 `EthnicGroupDef`。
- 待拍板：外观标签是否需要在族群层留一个引用键，还是完全归 DNA / Race 系统。

## 6A. 派系系统（借鉴 CK3 取舍，我方更拟真）

### 6A.1 借鉴 CK3 的部分

- 派系由持有共同诉求的人物与头衔组成，有领袖、成员、诉求与诉求完成度；
- 派系通过意见、施压、谈判、升级叛乱等链条影响统治者；
- 诉求与现行法律域、资格条件、领地分配挂钩，不是孤立的好感度数字。

### 6A.2 不照搬 CK3 的部分

- 不预设四类固定阵营标签（密谋 / 贵族 / 人民 / 教会），派系按真实利益关系动态聚合；
- 不把诉求写成不可扩展的固定枚举，诉求由成员共同利益类别合成；
- 不照搬 CK3 固定的投票与决议流程，诉求表达融入日常政治互动；
- 派系不等同于战争团体：多数阶段只形成压力与谈判关系，叛乱是升级后的结果之一。

### 6A.3 我方拟真方向

- 成员聚合依据：血缘家族、领地相邻、共同利益类别（阶层、信仰、文化、语言、地域、经济利益）、现任头衔与法律处境；
- 派系诉求引用法律域（见 4.0）：要求调整某一域法律、获得某类资格、改变领地分配规则；
- 领袖资格走 5.5 硬约束过滤，领袖与成员权重走 7.5 权重分离原则。

### 6A.4 性能约束

- 派系成员、领袖与诉求只在事件触发、法律变更或月度结算时刷新并缓存；日常运行只读缓存；
- 不满度与凝聚力增量式更新，不在每帧全量重组派系；成员多时按利益类别分组计算，避免两两比较。

## 7. 键名管理与条件过滤

### 7.1 命名空间

| 命名空间键 | 对象 |
|---|---|
| `realms` | 政治实体 |
| `cultures` | 族群/文化 |
| `faiths` | 信仰 |
| `titles` | 君主 / 官僚 / 爵位头衔（第 5 节，原 `offices` 并入） |
| `families` | 家族 |
| `persons` | 人物 |
| `settlements` | 聚落 |
| `regions` | 法理区域（第 8 节） |
| `armies` | 军队 |
| `buildings` | 建筑 |
| `institutions` | 机构 |

实体创建或自主生成时自动生成键名；存档持久化；同一命名空间内键名唯一，跨命名空间不冲突。用户自创实体由键名系统登记，不依赖显示名查重。法律域、法律组、题、子题等系统归类名属于内部机制，不进入上述可见键名空间，也不登记为实体显示名；其界面文案只按 4.0 的内部/可见分离规则走 locale。

### 7.2 四段过滤（对应 CK3 `can_create` / `can_have` / `can_pass` / `valid_character`）

1. 可创建：新建/生成时能否取用该名或该头衔；
2. 可保留：既有名号在政体条件变化后是否仍保留（对应 `can_keep`）；
3. 可通过/可任职：法律、头衔能否在当前组合下开放；
4. 可传承：名号随继承传递时是否保留。

### 7.3 过滤字段（比 CK3 扩充，含我方语言字段）

文化、族群、信仰、语言、法理区域、行政层级、政体形态、发展阶段、规模区间、地形、气候、性别、身份阶层。过滤优先于词库抽取；权重只在通过过滤的候选池中排序。

### 7.4 数量上限（可选，非强制）

每个命名空间 + 上下文可设 `max_uses` 上限；字段可空，空表示不限。命名池规则沿用 TTHTOM 四类（`literal` / `affix` / `generation` / `template`），池归属命名空间与文化隔离，每条规则增加 `conditions` 过滤段与 `max_uses`；`locale` 只作渲染层，不参与资格过滤。

### 7.5 硬约束与权重分离（通用原则，跨系统适用）

- 硬约束：可创建、可保留、可任职、可传承、资格字段等条件不通过时直接排除，**不受任何权重影响**；不存在"权重高就能绕过资格"。
- 权重：只在通过硬约束的候选池内排序，用于命名抽取、席位分配、头衔候选排序、诉求代表权重等。
- 该原则与 5.5 头衔资格、4.9 罪名定义引用、派系候选（第 6A 节）保持同一套口径；各系统只缓存各自通过硬约束后的权重排序结果，避免每帧重扫。

## 8. 自生成法理区域模型（预留，待地块/锚点/聚落成形后实现）

### 8.1 定位

法理区域不是预定义固定省份，也不是 TTHTOM 静态省份簇。区域由地块与聚落聚合生成，随文化、族群、地理、世界观、政治与行政规划的长期影响漂移；层级嵌套不超过 2~3 层，与行政层级挂钩。

### 8.2 数据字段（预留）

- `region_id` 键名（`regions` 命名空间）；
- `parent_region` 上层区域引用；
- `member_tiles`、`member_sites`（锚点/聚落引用）；
- 法理归属、实际控制、文化归属三状态分离；
- 漂移指标：文化相似度、行政整合度、距离、道路连通度；
- 与行政层级的挂接键。

### 8.3 与现有设计的边界

地块保留生物群系、地理、产物等记录职责；区域只做法理归属与聚合关系，不复制地块状态。军事占领对法理主张打折扣：攻下首府后先完成控制，周边聚落与领土进入控制读条，再逐步转化法理主张（该占领读条机制后续单独设计，本稿只登记接口位）。
