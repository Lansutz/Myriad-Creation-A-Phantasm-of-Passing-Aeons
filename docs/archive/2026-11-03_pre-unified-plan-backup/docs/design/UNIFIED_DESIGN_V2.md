## 1. 术语表（先严格定义，禁止混用）

| 术语 | 定义 | 不指 |
|---|---|---|
| **族群（ethnos / people）** | 以自称、血缘想象、语言/习俗标记、历史记忆形成的"什么人"；可嵌套（氏族→族群），可跨政权 | 不等于"民族（nation）"；不是"语族" |
| **大起源（heritage / macro-origin）** | 跨族群的共同历史来源/文明谱系标签（迁徙、祖先、经典、王朝记忆） | 不是生物种族；不是语言谱系 |
| **文化（culture）** | 可嫁接在族群/大起源上的**传统组合**（语言、习俗、生产、仪式、政治传统…），可改变 | 不是认同本身；不是一个数值 |
| **认同（identity）** | 对"我们是谁"的归属；载体=族群/大起源；有边界与显著度 | 不是文化相似度 |
| **语言（language）/ 方言（variety）** | 音系、词库、形态、语义规则的交际系统；有谱系与接触 | 不是认同层；语族只是语言学分类 |
| **民族（nation）** | 近代政治共同体概念；由民族主义建构 | 不是族群 |
| **民族主义（nationalism）** | 以民族为政治共同体边界的思想/运动 | 不是族群意识本身；其"公民权"前提是**普遍公民权**，不是古代城邦/罗马公民权 |
| **民族国家（nation-state）** | 以民族为政治单元的主权国家形态 | 不是王朝/帝国/城邦 |
| **国界线（state border line）** | 主权领土之间的**线性划定**（界标、界约、地图线） | 不是"边界概念/边疆/边境地带"这种笼统说法 |
| **印刷资本主义（print capitalism）** | 机械化印刷+出版市场+方言/通用语标准化形成的"印刷共同体" | 不是雕版印刷/活字印刷/某一种印刷工艺 |
| **普遍公民权（universal citizenship）** | 法律成员身份扩展到共同体全体成员（超越等级/地域/财产/性别等限制；Marshall 三要素） | 不是城邦公民权、罗马公民权、城市市民权、臣民身份、国籍；详见 [LAW_DECREE_AUDIT_AND_REDESIGN.md](LAW_DECREE_AUDIT_AND_REDESIGN.md) §2 |
| **科层制官僚（bureaucratic hierarchy）** | 按职务等级、书面规则、分工、档案运作的行政组织 | 不是"官僚制度"这种笼统词 |
| **常任文官制（permanent civil service）** | 非政治任命、长期任职、按考绩晋升的职业文官体系 | 不是世袭/恩荫/买官 |
| **部会制（ministerial departments）** | 按职能划分的中央部门（部/会）与部长责任 | 不是笼统"官僚制度" |
| **科举/文官考试（examination recruitment）** | 以考试选拔文官的特定制度（区域变体：科举、文官考试、九品中正→考试） | 不是"官僚制度" |
| **大起源（Heritage）** | 见上；代码字段 `CultureData.heritageId` | — |

## 2. 认同 / 文化 / 语言：统一模型

### 2.1 载体与嫁接

```
IdentityCarrier（认同载体）
  ├─ EthnicGroup（族群）：氏族 → 族群；不引入"语族"
  └─ Heritage（大起源）：跨族群的共同来源/文明谱系

Culture（文化）：可嫁接到 EthnicGroup / Heritage 上
  ├─ languageId（语言/方言）
  ├─ traditionIds（传统组合，按 TraditionCategory 分类）
  ├─ ethosId / faithId / 其他标记
  └─ 嫁接关系可因通婚/迁徙/政治/经济/宗教而改变
```

- 现有代码：`CultureData.ethnicGroupId`（族群）、`CultureData.heritageId`（大起源）、`CultureData.languageId`、`traditionIds`——**已有嫁接字段**；缺 `Heritage` 内容目录（加载器支持 `Base/Heritage/Heritages.json`，但 Base 下无 Heritage 目录）。
- 不引入"语族"作为认同层；`LanguageFamilyNode` 只服务语言学/命名。

### 2.2 文化分离（需要实际测试，不能拍脑袋）

- 机制：距离/阻隔 + 地理地貌差异 → 物产与生活方式变化 → **传统项变化**（新增/替换/组合/失传），文化才分离。
- 载体：`TraditionCategory`（Habitation/Production/Political/Ritual/Societal）+ 传统因子（SettlementDegree/SeparationTendency/FusionTendency/ResourcePreference）。
- **不用抽象相似度当驱动力**：`CultureSimilarity` 只是派生度量；分离/融合判定应在传统项与行为上。
- **必须实际测试**：同一套地理/接触条件下，不同参数（距离权重、通婚、贸易、政策、地理阻隔）跑 200–500 年，观察传统组合是否产生稳定分歧；通过标准：
  1. 无阻隔且物产/生计相同的两群体不分离；
  2. 有稳定阻隔且生计变化的两群体在 N 代内出现不同传统项；
  3. 通婚/贸易高时差异收敛；
  4. 参数扰动下结论稳定（不靠单一阈值）。
- 结论需要实验报告，而不是理论假设；测试不过就调整机制。

### 2.3 认同分离（政治整合；语言分离更易代码化）

- 机制：一个认同下可挂多个文化；当政权分裂成两个或多个，且**分离持续时间超过此前统一时间**（更真实的判定：政治整合度跌破阈值 + 法律/精英/制度分道），认同才分离。
- 认同融合：共同政权/法律/公民权/精英联姻/共同叙事。
- **语言分离比文化分离容易实现**：语言距离（音系/词库/形态）、接触强度、拆分时间可直接算法化；文化分离依赖传统项与行为，需要实验调参。
- 代码需要：`IdentityHistory`（统一区间、政权归属、分离事件、整合度），避免只用 `parentCultureId`/`allowsBranching` 的近似。

### 2.4 语言差异的意识（何时命名）

```
P(认成另一种语言) = f(接触强度, 互通度, 边界强度, 标准化, 时间)
互通度 = w1·核心词重叠 + w2·音系距离 + w3·形态差异（不对称）
```

- 触发 `LanguageBoundaryRecognized`：记录观察者/对象语言/年份/原因/互通度/自称/他称。
- 先认知后命名；未接触不命名；通用名（地图/编年史）后立；各族群名并存。
- 命名必须来自语言生成（§3），不是随机拼写。

## 3. 命名 / 语言学：音节、词、语义、合法性

### 3.1 生成模型（词，不是词根）

- **音系**：辅音/元音特征、声调、音节模板、禁音/响度、重音。
- **词库/语素**：每个词（lexeme）有词形+语义+词性+语域+词源；语素分类（含词根分类）由语言学系统提供；词可由多个语素/词复合。
- **语义分组**：抽象概念（自由/正义/荣耀/命运/王权）、物体/资源（水/石/铁/盐/木/马/鱼）、地点/地貌（山/河/湖/海/谷/原/岛）、方位（东南西北上下内外）、人物/群体（人/民/父/母/王/祭司）、动作/事件（建/渡/战/居/守）。
- **合法组合**：
  - 音系合法（音节/禁音/响度/韵律）；
  - 形态合法（词类/格/数/敬语/性）；
  - 语义搭配合法（动作配对象、通名配地貌）；
  - 历史/禁忌（避讳、禁忌词、尊号）。
- 命名类型：人名、地名（地域/聚落）、省份名、头衔名、族群名、语言名、神名；各有 pattern 与合法性规则。
- 例子：法兰克人——**政治联盟（萨利安人等）→ "自由人"的民间词源/他称 → 族群认同 → 法兰克人之地**。名字可以是政治/民间词源产物，词源与认同形成分开记录。

### 3.2 Data Forge 接入

- `language-families.json`（Glottolog）已接；
- `conlang-inventories.json` → `LanguageDef.phonemeInventory`；
- `core-concept-lists.json` → 语义组/核心词/互通度；
- Forge 的 07 协议（合法性状态、语素类型、FrameNet 框架、韵律）作为**游戏命名合法性 schema 模板**（XRiver 数据只是单语言样本，不是通用数据）；
- PHOIBLE/WALS/Grambank/UD/D-PLACE/Seshat 只做设计期校验/报告，绝不进包；
- 游戏侧 `DatasetIntegrityTests` 已强制 `_generated` 只允许 redistributable、source/lock/license 一致。

## 4. 头衔 / 政治实体 / 官员因子（我们与 CK3 的分界）

- **头衔 ≠ 地理区域**：CK3 把二者绑死；我们分开：
  - `TitleInstance`：`blueprintId` + `polityId`（`IPolityRef` 政治实体接口字段）+ `holderCharacterId` + `TitleBinding`（Personal/Territorial/Office/Elective/Claim/Union）+ `deJureRegionIds` + `deFactoRegionIds` + `claims` + 历史。
  - 头衔可以没有领地（名义头衔）、多重宣称、同一区域多重头衔；地理只是绑定字段之一。
- **可编辑**：玩家/AI 可改绑 polity/辖区/持有人；有合法性/稳定度/外交代价；AI 在头衔产生、死亡、征服、联姻、选举时尝试接合；失败虚悬。
- **缺失字段**：政治实体本身（`IPolityRef`/`PolityRegistry`）——必须先补。
- **官员因子**：`OfficeFactor`（economy/control/military/judiciary/religion/diplomacy/administration…）+ capabilities/constraints；`TitleBlueprint.factors` 决定能做什么；UI/AI 可编辑（受法律/政体限制）。

## 5. 货币 / 灾害 / 性能（简述，详见专项文档）

- 货币：地区化、具体化——沿海部落贝壳、内陆珠子、谷物计量、硬币、纸币、信用；发行者链（附庸用宗主货币）；不同政权同材质不同名；价格锚=本地工资天数；兑换/拒收/灭亡货币折价。参考 Earth `walkeco.js`；升级现有 `CurrencySystem`（单名/阶段）为 `CurrencyDef + Wallet + ExchangeRate`。
- 灾害：飓风可合并、登陆后按摩擦/水汽衰减（不瞬间消失）、地形先于气候；灾害按具体物产/建筑/人口结算；北美飓风是风险因子，矿/大型牲畜才是更直接约束。
- 性能：学 civ-atlas 的计算组织（typed arrays、事件堆、检查点、计算/渲染分离、确定性），不学 Earth UI。

>
> **较早修正**：本章早期稿里的"中央集权行政/中央集权思想"表述不专业，已由
> [INNOVATION_REDESIGN_RESEARCH.md](INNOVATION_REDESIGN_RESEARCH.md) 修正：正确概念是 **单一制（unitary state）**、
> **领土主权（territorial sovereignty）**；"中央集权化"是过程/程度，不是可研究条目。所有 `*术` 类命名也按该文改为具体工艺/制度名。
> 以该研究文档为准。


### 6.1 现状问题（185 条，实测 `Innovations.json`）

1. **数量少且粒度不均**：185 条，很多是"制度/技术"大词，缺具体制度变体；部分具体条目（如奇普统计）与全球通用条目混在一起。
2. **笼统概念**：`503 官僚制度`、`502 中央集权`、`206 印刷术`（后又 `979 活字印刷`）、`600 文字` 等。
3. **前置不合理/过硬**：例 `504 科举制度` 前置 `[945 九品中正, 205 造纸术]`——科举不是从九品中正"技术派生"，造纸也不是必要条件；`205 造纸术` 前置 `[204 纺织机, 600 文字]`——纺织机不是造纸必要前提；`1018 民族国家` 前置 `[1017, 503 官僚制度]`——官僚制度笼统。
4. **重复层级**：`206 印刷术` 与 `979 活字印刷` 同时存在；`502 中央集权` 与 `958 中央集权思想`；`822 文书行政`、`941 上计`、`942 考课`、`944 俸禄` 之间缺少清晰分层。
5. **前置不精确**：`503` 前置 `[502]` + any `[822,949 奇普统计]`——用"奇普统计"作为全球官僚制度替代路径不合理；`1017 民族主义` 前置 `[1016 报纸, 600 文字]`——印刷资本主义/普遍公民权/国界线均未出现。
6. **缺少门槛理由**：没有 `prerequisiteRationale`、没有 `effects` 的明确落点，难以审查。

### 6.2 精确化规则（硬约束）

1. **一概念一条**：一条革新只指一个可定义的概念（Idea/Technique/Institution/Practice/Law/Office/...）；若一个词有多个历史指称 → 拆。
2. **名词必须具体**：制度类必须带类型/范围（例：`常任文官制`、`部会制`、`郡县制`、`行省制`、`科举`、`文官考试`）；技术类必须带工艺（`雕版印刷`、`活字印刷`、`机械印刷`）；思想类带主张（`中央集权思想` vs `中央集权行政`）。
3. **禁止伞形词可研究**：如"官僚制度""印刷术""中央集权""公民权"只能作为 `InnovationCategory`（分类），不能作为可研究条目；具体条目挂在分类下。
4. **前置必须必要且可解释**：每个前置写 `rationale`（为什么没有它不行）；除非确有历史替代路径，否则不用 `prerequisitesAny`；`any` 项必须同抽象层级、同类型。
5. **时代单调**：前置 `era ≤ 本条目 era`；跨时代门槛用 `eraGate` 显式字段，不用隐式。
6. **效果落点**：每条革新必须声明解锁什么（`UnlockRule`：阶层/身份/职业/文化特质/教义/建筑/政体/法律/货币/命名 pattern…）或明确是"知识节点"。
7. **区域/文化变体**：不搞单一路径；用 `prerequisitesAny` 表示替代制度（如 `科举` vs `文官考试`），但替代项必须都能导向同一效果。
8. **可考证**：`termEn`、`definition`、`scope`、`sources`（参考来源）字段，避免"说的不具体"。

### 6.7 扩充目标（不是 185 条，而是每条更精确）

- **目标数量**：约 350–500 条（现有 185 条，需拆/补约 200–300 条）；按 26 个 `InnovationField` 分域，每域 15–30 条，时代 0–5 分布均匀。
- **优先拆的伞形词**：官僚制度、中央集权、印刷术、公民权、边界概念、封建制度、庄园制度、行会、银行、大学、常备军、法律（成文法/民法典之外）、宗教制度等。
- **区域变体**：不追求单一科技树；同一效果允许多条替代路径（东亚科举/伊斯兰迪万/欧洲文官考试/拜占庭官僚），用 `prerequisitesAny` 与 `variantOf` 表达。
- **内容来源**：用 Data Forge 式的数据管线管理定义/术语/来源；每条必须写 `definition/termEn/sources`；避免"说得笼统"。

### 6.8 校验（自动化）

1. `InnovationSchemaTests`：字段完整（termEn/definition/kind/category/prerequisiteRationale/unlocks）、ID 唯一、前置 ID 存在、无环、`era` 单调。
2. `InnovationPrecisionTests`：伞形词黑名单（官僚制度/印刷术/中央集权/公民权/边界概念…）不得作为可研究条目；前置不得含伞形词。
3. `InnovationPrerequisiteTests`：`prerequisitesAny` 至少 2 项且同类型；`rationale` 覆盖所有前置；`unlocks` 非空或标记 `knowledgeOnly`。
4. `NationalismGateTests`：缺国界线/印刷资本主义/普遍公民权任一 → `1017` 不可研究；三者齐备且时代满足 → 可研究；`1018` 需 `1017` + `国界线` + `常任文官制`。
5. `InnovationContentSizeTests`：数量/分域/时代覆盖达标（防止只有 185 条）。
6. 旧档迁移：`legacyIds` 映射；`503/502/206` 等旧 ID 读档时映射到具体条目，不能丢失研究进度。

## 7. 统一后的系统关系

```
环境/物产（具体 goods + 产量/价格）
   ↓ 产物推动
革新（精确概念、拆分、可验证前置）
   ↓ 小绑定（UnlockRule）
阶层/身份/职业（只有完成某革新才出现）
   ↓
文化（传统组合）/ 宗教（教义）/ 语言（音系词库）
   ↓ 嫁接
认同（族群 / 大起源）
   ↓ 政治整合/分裂
头衔（TitleInstance）/ 政治实体（IPolityRef）/ 民族主义→民族国家
   ↓
命名（自称/他称/通用名）与编年史
```

- **语言分离**：算法化（音系/词库/形态距离+接触+时间），可测试；
- **文化分离**：传统项+地理/物产+接触，需实验调参；
- **认同分离**：政治整合/政权分裂时长，需 `IdentityHistory`；
- **民族主义/民族国家**：严格门槛（国界线+印刷资本主义+普遍公民权），之后才有民族国家；
- **头衔**：与地理分离、可绑定政治实体、AI 接合；
- **革新**：精确概念、拆分、前置可解释、效果落点明确。
